# 运算时间优化更新方案

日期：2026-10-28。状态：0.9.1 已交付第一轮来源索引及安全前缀主路驻留，当前代表性流程通过原数值和来源核对，原配置 CPU/GPU 混合流程三次中位数分别为 46.76/61.74 秒；完整通用调度、全部模块原地执行和复杂旁路生命周期仍按本方案后续推进。已实施范围与性能见 [0.9.1 后端说明](BACKEND_EXECUTION_0_9_1.md)。

2026-10-29 后继方案：[模块化处理流执行优化](PROCESSOR_EXECUTION_OPTIMIZATION_PLAN.md)。依据39次独立对照，下一轮重点转向所需像素范围、静态几何、GPU批量与设备边界；下文565.18/700.64秒及来源约281秒均为第一轮改造前的历史基线。

本轮将执行器升级为按所有权、依赖和预算推进主路数据：裁剪、编辑或归约后的结果接管当前工作数据，没有后续使用者的旧输入及时释放；独占且适合原地执行的缓冲区直接复用。可容纳的当前数据完整保存在内存或显存中，不能完整容纳的部分分块保存和消费。同时独立优化时间与来源索引，消除逐窗口重复回溯。模块顺序、参数、精度、时间配对和科学含义保持不变。

优化继续服务于视频数据预览和数据处理：普通播放保持按需读取，阶段检查与正式任务共用数值实现，计算进程中的结果可核对、可导出，工作台不会为了预览而预计算整段数据。

## 实测问题与更新目标

当前代表性流程为：时间范围 → 强度标定 → 双幅配准 → ROI 裁剪 → 时序统计均值 → 固定 τ 的 g²。输入 10284 帧、600×832、uint16，关联 W=1001、τ=0、输出步长为 1，输出 9284 个 float64 标量。

两次运行使用相同来源修订、模块顺序、科学参数和资源预算，区别为默认设备。GPU 运行中的配准实例明确选择 CPU，因此是混合流程。两次均只有一轮，不作为重复中位数基准。

| 环节 | GPU 混合流程 | 全 CPU 流程 |
| --- | ---: | ---: |
| 来源内总耗时 | 700.64 秒 | 565.18 秒 |
| 来源映射 | 283.22 秒 | 280.68 秒 |
| CPU 数值计算 | 180.17 秒 | 272.26 秒 |
| GPU 主机调度 | 71.74 秒 | 0 |
| 上传与回传 | 153.36 秒 | 0 |
| 输入读取 | 10.44 秒 | 10.44 秒 |

全部 9284 个输出的有限值掩码一致，最大绝对差为 2.22×10⁻¹⁶；逐输出来源记录与偏移索引逐字节一致。主机调度、上传和回传包含同步等待，不能解释为纯 CUDA 内核时间或纯传输时间。

更新目标按优先级排列：

1. 将顺序滑窗的时间来源查询从随“输出数 × W”增长，降为随直接上游样本数及输出数线性增长。
2. 让裁剪和修饰后的结果接管当前主路缓冲区，优先转移所有权、复用可安全原地执行的内存并释放无用旧输入；本例依次由 ROI、双路标量序列承接数据。
3. 在总工作内存、计算缓存和显存上限内选择完整驻留、分块流水或临时磁盘存储。
4. 减少 CPU/GPU 边界的重复传输及小结果的逐个同步，保持显式设备选择。
5. 每项优化单独记录收益和资源代价，再验证组合后的完整工作流。

## 为什么现有实现会重复回溯

现有 [SequenceEngine](../src/eip/sequence_engine.py) 通过 `get(stage, index)` 按需向前序模块取一个样本；时间与来源通过另一条 `ref(stage, index)` 路径取得。这种结构适合原始帧预览、随机定位及初期有界执行，但不能充分利用正式顺序运行的访问规律。

数值结果按阶段和样本放在共享 LRU 缓存中。大图、ROI 和只有两个数的归约结果一起参与淘汰，缺少针对未来访问的保留策略。g² 的滚动累计已减少多数重复求和，但缩窗、随机访问、周期性数值重建仍需要上游样本；被淘汰的小信号会重新触发标定、配准和读取。

来源映射又有独立重复工作：`correlation_reference` 对普通固定 τ 关联的每个输出重新遍历 W 对时间引用，每一对再经过前序模块递归返回。本例约有 `9284 × 1001 × 2 = 18586568` 次上游时间引用请求，另有中心引用。τ=0 时两次查询还指向同一帧。当前增量来源统计只覆盖部分固定中心扩大 W 的场景。

因此，保存前序数值结果能解决一部分数值回算；时间和来源也要生成可直接访问的索引，才能消除另一条路径的递归开销。

## 按阶段保存结果的执行方式

当前主路数据是正在交给后续模块使用的数据，后序可以直接消费、替换或取得其独占所有权；为了复用、随机访问而另外保留的历史副本才属于额外缓存。单向流程默认向前交接当前数据，不默认同时保存每级输入输出。

阶段结果保存是把某个模块真实输出的数据、类型、轴、时间和来源映射一起固定下来，后续模块直接读取。它是执行计划的一部分，不增加隐藏算法，不改变模块流程的唯一事实来源。

| 方式 | 适用条件 | 后续读取与释放 |
| --- | --- | --- |
| 完整内存驻留 | 当前主路数据及其峰值工作集在主机预算内 | 独占缓冲区向后交接，满足条件时原地复用；最后一个使用者结束后释放 |
| 完整显存驻留 | 连续 GPU 模块的阶段输出和工作数组可同时放入显存预算 | 后续 GPU 模块直接访问设备数组；回传按实际交付需要执行 |
| 分块流水 | 整段输出过大，但模块可按已声明的空间或时间上下文执行 | 传递块、重叠区和状态；所有使用者消费后释放该块 |
| 临时磁盘阶段存储 | 数据过大且后序需要多遍、较远随机访问或长窗口回读 | 按顺序生成真实阶段输出，使用磁盘映射或分块文件读取，避免重新执行前序算法 |
| 兼容按需执行 | 插件尚未声明必要能力，或范围很小、物化得不偿失 | 沿用已验证路径，记录所选方式及原因 |

时空裁剪后，保留区域直接成为新的当前主路数据，被舍弃的区域在没有其他使用者后尽快回收。执行器应优先让显著压缩数据的节点完成这种交接，再决定是否完整驻留、按块消费或额外缓存。多个可逐样本执行的前序模块可在同一个块内按原顺序连续计算；不要求每个模块都先保存整段，也不因逻辑上有多个模块就复制多份数组。

对当前流程，推荐执行路径是：

```text
CINE 按块读取
  → 每块依次执行 标定 → 配准
  → ROI 接管工作数据，释放该块已无依赖的裁剪前大图
  → 可完整容纳时保留整段 ROI；否则按 ROI 块继续向前传递
  → 均值结果接管工作数据，释放已消费且无依赖的 ROI
  → 保留完整的 10284×2 双路信号及时间索引
  → g² 从双路信号直接取样，按既有规则滚动和重建
  → 数值结果与完整来源记录导出
```

如果 ROI 紧接均值且没有 ROI 的额外使用者，执行计划也可逐块完成 ROI 和均值，无需强制物化整段 ROI。两种方式都由裁剪后数据接管主路，并及时释放已无用途的大图。均值位置不变，模块边界不暗中量化、降采样或合帧。

## 缓冲区复用和原地修改

中间模块和修饰模块都应优先采用可避免复制的执行方式，但模块分类本身不能证明原地修改安全。ROI 与时间裁剪主要选择数据；增益、归一、平滑、统计和类型转换仍有实际运算，其类型、邻域和有效值规则决定内存方案。

| 操作 | 优先执行方式 | 需要满足的条件 |
| --- | --- | --- |
| 时间或空间裁剪、通道选择、轴重排 | 使用视图或转移所保留数据的所有权；大底层分配已无用途时压紧保留部分 | 正确保留索引、步长、坐标、时间和贡献；视图不能长期拖住无用大数组 |
| 元素级增益偏置、固定尺度归一等 | 在语义允许时写回独占缓冲区，或复用已释放的同类型缓冲区 | dtype、精度、运算顺序、舍入、溢出、NaN/Inf 和显式单路目标保持原定义 |
| 均值、点提取、阈值、灰度或精度转换等改变形状或类型的操作 | 将结果写入更小或目标类型的缓冲区，完成交接后释放输入 | 不强行让不同 dtype 共用同一解释；输入输出交接峰值计入预算 |
| 空间平滑、配准插值、时间加窗与合帧 | 使用必要的行、块、窗口暂存或可复用输出缓冲区；满足条件的核心区消费后回收 | 不能在邻域尚未读取时覆盖其原值；保留边界、掩膜、权重和贡献规则 |
| 来源已有旁路使用者、共享预览、只读映射或缓存快照 | 原数据继续只读；需要写入时为写入者分配独立缓冲区，或等其他使用者完成后转移所有权 | 只在确实发生冲突时复制，且计入预算 |

这里可被修改的是任务独占的工作数据。源文件、共享读取缓存、预览数据及已经交付的结果不因为主路的原地执行而改变。当前缓存返回的只读数组不能通过简单恢复可写标志直接改写；执行器必须显式授予独占写入权，或在写入者第一次修改时分离数据。

ROI 切片本身常可零复制，但它可能仍引用整幅图的底层分配，删除原变量并不能释放被切掉区域占用的内存。优先采取两种有实际释放效果的方式：对满足布局及重叠安全条件的独占缓冲区做原地压紧并归还可回收空间；或者将保留区域一次写入紧凑的目标缓冲区，再释放大底层分配。对于分块读取，目标可以直接是预分配的 ROI 当前数据，峰值只需包括该目标与正在处理的大图块，无需先物化整个裁剪前序列。

按底层内存分配而非视图对象跟踪所有权、仍存活的使用者、读写状态和容量。同一块内存经多个视图引用时只计一次；后续 GPU 异步内核尚未结束读取时不得回收或覆盖，使用明确的流依赖和完成事件管理，而不在每个模块后强制全设备同步。

原地执行也不能用低精度中间值替代既有算法。例如 uint16 输入的增益偏置如果原定义使用浮点中间量后统一舍入，不能为了原地执行先在整数里乘、截断再加；应保持数值定义，必要时使用受预算约束的暂存块。

## 当前数据的内存估算

下表仅计算数值数组，不含掩膜、坐标网格、统计状态、对象开销、解码器及临时副本。

| 阶段 | 全部 10284 个样本的数值大小 | 调度判断 |
| --- | ---: | --- |
| 原始 600×832 uint16 | 9.56 GiB | 当前任务份额放不下，按需或分块读取 |
| 标定后的 600×832 float64 | 38.25 GiB | 按块向后传递 |
| 配准后左右各 596×388 float64 | 35.44 GiB | 按块向后传递 |
| 裁剪后的左右各 142×132 float64 | 2.87 GiB | 在任务峰值预算内可作为当前主路数据完整驻留，裁剪前大图不再同时长期保留；否则按块接管 |
| 均值后的 10284×2 float64 | 164544 字节，约 160.69 KiB | 完整接管主路，消费结束的 ROI 随即释放 |

现有主机设置为总工作内存 10240 MiB、预览 1280 MiB、计算缓存 2048 MiB。当前分配中阶段检查另占 256 MiB，正式任务份额为 8704 MiB。不能用 10240 MiB 直接判断一份 9.56 GiB 输入能否全载入。

2.87 GiB 的 ROI 作为唯一当前主路数据，是否驻留由这 8704 MiB 任务份额和同时存活的工作集决定，不受 2048 MiB 额外缓存额度单独卡住。可通过边读边裁剪建立紧凑 ROI 数据，并释放每个已完成大图块，避免将整段 35.44 GiB 配准结果与 ROI 同时物化。

一份 float64 时间列还需要约 80.34 KiB；真实来源索引、PTS、触发时间、已知标记和贡献映射另计。即使完整图像放不下，本例的双路信号与基本时间索引仍很小，足以成为优先保存点。

## 预算和缓存释放规则

### 统一计算峰值

完整驻留必须校验同时存活的数据，不能只判断单个输出的大小：

```text
主机峰值 = 当前主路及仍被使用的分支数据 + 确有需要的历史缓存
         + 交接时尚未释放的输入和正在构建的输出
         + 工作数组和重叠区 + 算法保留状态
         + 时间来源索引 + 上传回传暂存 + 预取块
```

显存也独立执行相同原则，并为 CUDA 上下文、内存池和库内部开销保留安全余量。主机内存与显存不能合并成同一个可用容量。

预算明确区分当前工作数据与额外历史缓存：当前主路缓冲区、仍需交付的分支及不可丢弃的算法状态计入任务工作集；为避免重算而额外保留的旧样本、副本与读取缓存受 `cache_mb` 约束，并可动态转移这部分额度。同一底层分配不重复计数，无用旧输入不继续以“缓存”为由保留。

所有分配仍受总任务峰值上限约束；额外缓存不能挤占必要工作数组，系统有空闲也不越过用户的总内存上限。运行计划记录 `current_main_bytes`、`pending_branch_bytes`、`history_cache_bytes`、`scratch_bytes` 及交接峰值，让预算分配可以核对。

GPU 阶段保存占用须作为显式保留状态进入资源计划；普通设备 LRU 与上传缓存的当前四分之一比例不能当成整段驻留能力的唯一判断。新的分配器必须合计阶段存储、普通缓存、工作数组和安全余量，再决定是否驻留，不通过更换分类名绕过显存总预算。

### 在最后一次使用后释放

“下游已有输出”不一定意味着全部上游输入都可释放。释放条件是：所有主路、旁路、统计拟合、参数依赖和后续窗口访问都不再使用相应数据，或这些需求已由可靠的阶段存储承接。

- 普通逐帧节点：该块的全部使用者消费后释放输入块。
- 时间窗口和关联节点：保留仍在后续窗口内的样本、重叠区和必要状态；移出窗口且无其他依赖的样本才可回收。
- 全域统计及引用其结果的参数：保留所需阶段存储，完成全源拟合后让下游继续使用，不因第二遍扫描重做整个前序流程。
- 数据截流、旁路信号和正式导出：视为真实使用者。当前任务末尾集中导出旁路的路径必须接入生命周期计划，不能在旁路交付前清空它的唯一输入。
- 阶段检查与普通播放：继续使用独立读取器及资源份额。正式任务释放内部缓存不能改变用户当前预览位置或关闭预览来源。

能够获得独占所有权的缓冲区直接交给下游复用。ROI、点信号等视图若仍持有已无用途的整幅图或上传大块，则按前述规则压紧或一次写入紧凑目标并释放底层大分配。避免为每级逻辑输出固定建立独立副本。

释放的是运行内缓存或已完成交付的临时载体；原始文件、正式输出、模块参数和来源快照继续保留。

## 内存不足时的分块方法

块必须携带实际样本索引、轴、空间原点、真实时间和贡献来源。块的大小由当前存活工作集与模块声明共同决定，不能只用“可用内存除以单帧大小”。

1. 编译每个模块的访问范围和上下文需求，反推输出块需要的上游样本。前序抽样、合帧和裁剪都参与映射，W、τ 继续按直接上游计数。
2. 为输出核心区分配输入块、时间重叠区和算法状态；相邻块复用仍有效的重叠数据或从阶段存储直接读取。
3. 数值、侧输出和必要来源信息完成交付后，推进消费者位置并释放不会再访问的块。
4. 窗口、随机访问或多遍依赖超出内存承受能力时，生成临时阶段文件，使用有界内存读写。预检磁盘空间，关闭映射句柄，取消或失败时明确标记并清理临时载体。

例如关联左窗口为 `[s,e)`、有符号延迟为 q 时，左右所需样本的包围范围是 `[s+min(0,q), e+max(0,q))`。延迟扫描应按所选延迟集合确定上下文；不能只加正延迟，也不能把文件帧率乘以时间冒充精确定位。

W 大于单块容量时，不能把每个块独立当成完整时间序列。应保留跨块滚动状态，或通过阶段存储访问真实窗口。块尾不重复输出，完整窗口规则保持一致。

## 时间和来源索引单独优化

### 编译可直接查询的映射

将不改变时间的标定、配准、ROI、空间归约等节点编译为时间映射透传；将裁剪、抽样、合帧和关联编译为明确的索引映射或贡献描述。查询输出引用时直接执行组合映射，减少逐层递归及重复字典构造。

每个保存点都携带轴、dtype、样本数、空间映射、来源修订和完整上游实例指纹。T、Q、W、N 的含义保持区分，静态记录不生成伪造时间。非连续贡献不能仅靠一个包围区间冒充完整成员集合；范围压缩须保留原有精确规则与包围范围标记。

时间列可在预算内整段保存，超额时采用分块索引或临时磁盘载体。源 PTS、CINE ticks 等整型字段保留原类型及时间基，不能先转成大绝对浮点时间再反推原始值，也不用平均帧率补齐未知时间。

### 增量维护关联窗口统计

对每个实际有需求的 q，使用真实配对时间计算 `delta(i,q)=time(i+q)-time(i)`。顺序滑窗维护时差之和、已知配对数及极值，窗口移动时只处理进入和移出的部分；极值使用单调队列或有界区间摘要，不能通过两个前缀极值相减得到。

- τ=0 时，同一样本的已知时间只查询一次；未知时间仍须按原规则反映在已知配对数中。
- 固定中心扩大 W 沿用增量路径；缩窗、变更 q、逆向及随机访问应正确重建或查询区间摘要。
- 大量 q 不同时生成无限的 T×Q 时间表；按活跃延迟、预算和实际请求建立索引。
- 时间已知配对数与 g² 的像素共同有效强度计数是不同对象，不能混用。
- 增量求和和分块可能改变浮点累加历史，时差统计使用明确容差与直接公式核对；极值、未知标记、配对范围和贡献成员保持精确。

## CPU 和 GPU 执行策略

保存点尽量位于连续同设备模块的边界或显著压缩数据的节点，避免为缓存把每一级 GPU 输出都回传一份完整主机副本。实际 CPU/GPU 边界按预算批量传输，消费者完成后释放不再使用的传输块。

当前代表性流程先保持原设备设置，测量阶段保存自身的收益；之后单独对照全 CPU、原混合流程、连续 GPU 配准至归约等配置。明确指定 CPU 或 GPU 的实例继续服从用户设置；执行器可以给出建议，但不能为追求速度覆盖显式选择。

标量 g² 不需要堆满显存。可将一批样本传入已有 float64 融合累计器，减少 Python 调度；批量表示调度单位，不等于合帧、改变有效集合或并行重排求和。保留当前必要的周期重建机制，先通过阶段保存降低重建时的取数成本。

普通播放不生成整段阶段存储。阶段检查只准备所选输出所需范围和上下文，必要的全源统计依赖仍完整执行并复用。所有方式复用相同模块数值实现。

## 实现位置与阶段交付

| 顺序 | 交付内容 | 主要位置 | 验证重点 |
| --- | --- | --- | --- |
| 第一阶段 | 来源映射组合索引、固定 τ 滑窗增量统计、引用查询计数 | `sequence_engine.py`，新增专用引用索引实现，`performance.py` | 取消重复窗口遍历；实际时间、负延迟和来源一致 |
| 第二阶段 | 当前主路所有权交接、安全原地执行、裁剪压紧、预算内阶段驻留及依赖使用完成后释放 | 新增 `stage_storage.py`、`execution_plan.py`，接入 `resources.py`、`sequence_engine.py` | ROI 接管并释放大图；当前工作数据与历史缓存分账；峰值包括交接中的输入输出 |
| 第三阶段 | 分块流水、临时磁盘阶段存储、旁路及全域统计生命周期 | `sequence_processing.py`、`sequence_delivery.py`、统计与窗口执行器 | 块边界、长窗口、多遍与旁路交付正确 |
| 第四阶段 | GPU 阶段驻留、跨设备批量与必要同步合并 | `gpu_pipeline.py`，复用现有 GPU 模块和融合内核 | 显式设备选择不变；传输与峰值有据可查 |
| 第五阶段 | 运行详情、旧记录兼容和完整性能验收 | `performance.py`、Web 任务详情、专项工具与文档 | CPU/GPU 实际设备、策略、资源和完整输出可核对 |

新执行计划是从模块流程和数据契约派生的调度结果，不引入第二套可独立编辑的算法配置。模块执行能力补充输入可否消耗、原地写入条件、类型及布局约束、邻域依赖和输出是否别名输入等声明；不能按“中间模块”或“修饰模块”的分类直接开放任意写入。初版优先支持能力已知的内置模块；第三方插件在统一契约中补充这些条件以及可缓存性、访问模式、随机状态和上下文声明后再纳入相应策略。已有插件兼容执行路径继续可用。

每个阶段都可独立验证和回退，随后再组合。第一、二阶段优先落地；第五阶段所需的基础计数应随前四阶段同步增加。

## 记录与界面反馈

运行记录增加实际保存点、保存方式、构建与读取耗时、数组和索引大小、预算及峰值估算、块大小、重叠范围、磁盘读写量、命中数、重复计算数和实际跨设备传输数。关键指标包括：

- 每模块实际求值次数与唯一上游样本数，区分必要重建、上下文重叠和非预期重复。
- 来源引用查询次数、时间索引构建与查询耗时，区分来源映射生成与来源文件写出。
- 主机与显存的阶段存储、普通缓存、保留状态、暂存及估算峰值，区分逻辑数组、内存池保留和驱动整卡占用。
- 原地复用、所有权转移、裁剪压紧、冲突分离的实际次数和字节量，以及旧输入释放时点；不能用“逻辑上已裁剪”代替底层内存确已不再被引用的证据。
- 阶段存储构建和读取计入互斥主机分类；嵌套耗时不重复累计，不能把新增预处理移出计时来制造加速。

任务进度显示正在准备的保存点和真实样本数量，准备整段信号时支持取消。运行详情按需展开策略，不在普通预览主流程增加必须理解的调度选项。旧运行缺失的新字段显示未采集，不能补造。

## 验收条件

### 数值和科学含义

- 同一流程分别强制完整驻留、多个分块尺寸及临时磁盘方式，输出轴、shape、dtype、含义和完整有限值掩码一致。
- 对照独立 g² 公式，覆盖正、零、负 τ，不对称延迟、奇偶 W、无效值、低均值、极小涨落、周期重建和随机访问；保持 float64 累计及共同有效样本规则。
- 覆盖 g² 前后的时间裁剪、取间隔、合帧、加窗，保证 W、τ 按直接上游计数；关联后的时间编辑不回改原定义。
- 验证 ROI 空间平均与区域总强度的 g² 仍有明确区别，不能移动统计位置来缩小工作量。
- 不均匀、未知时间与缺帧记录的来源索引逐项与直接回溯参考核对；本例所有 9284 个来源记录要求与原记录一致。

### 生命周期和预算

- 测试输入与输出同时存活时的峰值、ROI 视图持有底层大图、上传暂存和双缓冲重叠，不能仅检查最终缓存大小。
- 对比独占输入与存在别名、旁路、只读缓存时的行为：允许复用时不增加不必要副本；发生读写冲突时只分离写入者；其余使用者和原始来源数值保持一致。
- 对比原地与非原地路径，覆盖整数舍入溢出、float64 中间量、dtype 改变、邻域覆盖、非连续布局和异步 GPU 消费；输出科学含义及数值容差一致。
- 测试保留区域接管后大底层分配不再被视图或缓存持有，以及 ROI 超过 `cache_mb` 但在任务工作集预算内时可正常作为当前数据驻留。
- 覆盖一个保存点被主路、多个旁路、截流导出、全域统计和参数绑定共同使用的情形；任何使用者未完成前不释放其唯一数据。
- 以紧预算、输出 dtype 在首样本确定、未知样本长度、超长窗口及随机访问触发策略选择，确保有界执行、明确失败或受预算约束的替代路径。
- 取消、算法异常、磁盘不足及来源修订变化均不发布完整结果；Windows 映射和设备资源按生命周期释放。
- UI 预览仍可播放、定位、查原值；阶段检查与正式结果在相同条件下数值一致。

### 性能

先用有独立参考的模拟数据验证计数和复杂度，再使用相同真实文件、流程与预算复测；真实输入保持只读，结果写入独立目录。分别报告单次结果和重复三次的中位数、缓存冷热、主机总耗时与进程总耗时。

本例第一阶段的目标是将来源映射从约 281 秒降到 10 秒以内，且顺序窗口的来源查询次数不再随 W 成倍增长。第一、二阶段合并后的完整 CPU 任务目标是相对原 565.18 秒减少至少 40%。这些是待实测的验收目标；阶段准备、磁盘存储、来源构建及原有数值和图形导出都计入总耗时。

对能完整保存的本例双路信号，前序压缩流程应按每个所需样本计算一次；额外求值须能由明确的上下文、数值重建或插件能力解释。对分块流程记录块重叠及实际读取放大，不能只报告最终输出吞吐。

GPU 继续使用真实 CUDA 核对，不用主机适配器推断性能。报告原混合配置与显式连续 GPU 配置的区别，即使某场景 GPU 较慢也保留结果。

## 实施边界与参考

本轮优化不增加工作模式，不改变模块顺序和统计定义，不降低 float64 关联精度，不删减来源信息或默认图形导出，也不把普通播放改成整段预计算。新的运行内阶段文件属于临时计算载体，不自动登记为正式处理结果。

继续使用现有预览引擎、模块目录、实例参数和结果协议；必要的新执行记录字段保持版本化。来源修订、上游参数、模块版本、选定范围、精度、设备以及依赖改变时，相应阶段存储和索引必须失效。
