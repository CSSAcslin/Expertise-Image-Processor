# 0.9.3 模块处理流执行优化

0.9.3 将局部数据需求和分块调度接入公共处理引擎。ROI、点、线与空间截面可以约束前序实际处理的像素；固定几何复用采样映射；连续CPU或GPU运算以预算内的块向前交接。优化适用于可组合的模块能力，不要求使用某条固定关联模板。

模块流程仍是算法配置的唯一事实来源。实例顺序、启停、参数、作用通道、版本、精度、真实时间和来源记录不变。原始视频播放继续按需读取，阶段检查、试算和正式运行共用数值定义；局部计算结果不能冒充完整中间图。数据与处理结果仍通过现有公共视窗查看、对比、导出和重新打开。

## 统一能力与实际执行计划

[全模块能力表](MODULE_EXECUTION_CAPABILITIES.md) 审查了当前36个内置模块，包含兼容节点。`execution_plan.py` 为各模块记录空间依赖、时间依赖、邻域半径、全输入校验、旁路交付及参数引用等条件；未知插件采用保守能力。

能力声明表示某种变换的资格。实际优化还取决于参数、输入轴、访问方式、设备和预算，不能根据模块分类自动开放局部执行、批量或原地写入。运行记录保留全部逻辑实例，同时记录实际处理范围、块数、设备传输、回退原因及计划指纹，便于解释一次任务具体采用了什么策略。

公共引擎默认启用优化；开发对照可以通过 `SequenceEngine(..., optimize=False)` 使用兼容执行路径。它是验证开关，不增加一套独立维护的用户算法流程。

## 空间选择向前约束实际计算

ROI、点提取、横纵轴线、任意线段、空间轴截面和双幅点 / 区域时序比较，从其直接上游请求必要范围。经过已适配的逐像素变换、固定配准或前序裁剪时，执行器合成坐标并缩小物理工作数组，随后仍按原模块顺序完成计算。

例如：

```text
固定强度变换 → ROI → 点提取
固定标定 → 固定双幅配准 → ROI → 空间均值
颜色排列 → 灰度 → 线段提取
高斯平滑 → ROI
时间取间隔 → 时间加窗 → 合帧 → ROI
```

这些流程复用相同范围执行器，不依赖后面是否存在g²。空间统计仍消费其完整直接上游范围；不能把后置点提取前推成只统计一个点。颜色操作保留明确的C轴，双路操作保留P轴和目标通道，形状改变后的标量、向量或R轴不伪装成图像。

任意线段使用原坐标生成采样位置，再转换为局部索引，避免重新生成局部坐标时改变半像素最近邻选择。双线性保留原邻居、权重和零权重无效值规则。局部缓存与完整阶段缓存保持分离，后续查看完整中间图仍得到真实完整输出。

## 固定几何与空间邻域

固定配准的共同范围先用轴向量计算，不为点请求预先生成整幅二维网格。请求区域的整数索引、有效掩码及双线性权重按固定映射复用；全图兼容调用也复用预编译数据，减少每帧重复的坐标转换、裁边和分配。映射缓存有界，CPU和GPU按各自执行边界使用对应数据。

高斯平滑的局部请求包含其半径所需邻域，再裁出真正结果。边界继续参照该模块完整输入，保留复制边界、有限权重归一及原无效位置，不把最终ROI边缘作为原图边缘。每节点的native类型恢复、显式精度与单路目标继续参与实际计算。

均值滤波保留完整输入兼容路径：原实现对当前完整输入检查有限性，并采用积分前缀累计。局部重新累计既可能漏报ROI外NaN，也可能改变累计与抵消的舍入历史，不能仅靠增加邻域就替换现有算法。

## 时间编辑与局部窗口状态

时间裁剪和取间隔按实际样本映射传递空间需求；时间均值、总和或精确分位窗口可以在所需空间区域维护原有状态。合帧继续保留全部参与样本及尾组舍弃规则，后续W与τ按编辑后的直接上游计数，Q不作为时间编辑轴。

局部时间状态按区域、实例和设备区分，使用有界缓存。嵌套窗口执行期间锁定活动状态，不能被内层请求淘汰或关闭。状态或精确分位暂存预算不足时，使用原模块兼容路径，不因新增优化让原来合法的大窗口失败。取消及关闭时回收状态和临时磁盘环。

普通预览与单次阶段检查不会为了这一优化准备整段序列。已有全源统计依赖仍按其声明范围执行，未知时间不会用平均帧率补造。

## CPU与GPU的有界块执行

正式输出通过 `iter_outputs` 按逻辑顺序交付，每个输出仍独立生成来源和原有导出字段。可适配的前序操作真正以批数据完成标定、逐像素运算、几何采样和空间选择；不是仅将上传分块、内部仍逐帧构造完整图像。

块大小同时受任务工作预算、实例上限、设备预算和暂存估计约束，最多使用有限样本块。原始源帧读取与完整校验仍计入处理时间。批量维度只用于执行，不能进入公开数据契约或被解释为合帧。

批量并非所有流程的默认最优方式。对单帧至少1 MiB、没有范围缩减或时间依赖的纯CPU局部变换链，正式交付保留逐帧执行，避免为凑批多复制整幅数据；小信号、局部选择和设备路径继续使用各自适配器。全幅控制组参与基准，防止只验证有ROI的流程。

显式CPU节点继续在CPU执行。GPU标定后接CPU配准时，可以缩小必须传输的输入域、批量回传，再由CPU完成真实配准；不跨该边界隐藏执行算法。实际设备与上传、回传字节进入记录，GPU占用率或显存使用量不作为性能验收目标。

### 顺序小信号关联的连续输出块

CPU路径对RAM中已驻留的 `(T,2)` float64双路标量提供 `CpuCorrelationBlocks`。以原顺序执行双精度标量累计，减少逐输出NumPy小数组调度；取消检查保留在输出与配对循环中。它直接共享现有主路信号，不另复制整段输入。空间图、Q / W扫描及其他不满足条件的输入继续使用原CPU关联实现。

实际CuPy设备上的固定τ、顺序T输出，若直接上游具有可完整驻留的紧凑float64双路检查点，可使用 `GpuCorrelationBlocks` 连续生成结果块。每个分量在时间方向沿原顺序累计，float64波动量、共同有效配对、最小均值和样本数规则保留，禁用FMA。

跨块延续状态，周期重建按全局T输出序号每256个输出执行。结果按块回传，来源仍逐条生成；已适配的逐点后处理可继续消费这批结果，并保留其精度和显式设备边界。额外状态、输出缓冲和后处理暂存计入块大小限制，配对更新量也约束单次启动规模。

这些路径仅接受满足资格的完整顺序交付。Q扫描、W扫描、随机访问、大空间图、稀疏窗口、非float64或无法建立相应直接检查点的流程保留兼容关联执行器。固定中心单调扩大W仍沿用其独立扩展规则，不能套用滑动T的256重建机制。小信号策略不会直接推广为大图的整段单线程内核。

## 完整依赖与输入校验

旁路与参数提供者属于真实消费者。`data_tap`继续交付截取点的完整上游数据；点、线或统计旁路保留自己的范围和正式 / 试算状态，后置ROI不能截掉它们的输入。当前在需要完整输出或尚未支持的依赖处使用兼容边界，保留后续可独立优化的片段。

带LUT的标定仍对完整有效输入检查码值范围，ROI外非法码值不会因局部计算被隐藏。配准前左右不同暗场仍按传感器中线选择偏置；尚不适合局部执行的组合回到原路径。固定归一先解析并校验尺度；空间变化的尺度未适配局部匹配时停止需求前推。

全域统计、兼容序列统计、自动直方图边界与统计引用继续读取真实声明范围。插件没有明确局部依赖和副作用声明时接收完整输入。算法错误、非法输入和GPU数值错误正常报错，不通过静默重跑隐藏失败或重复旁路导出。

## 内存交接与保守预算边界

裁剪和归约后，紧凑结果接管当前主路。能够独占交接的结果直接向后传递；小视图若仍引用大底层分配，则压紧保留部分。完成最后消费的前序缓存及时释放；共享预览、只读缓存或仍被异步GPU使用的数据不原地覆盖。

原帧及完整校验结果使用有界短期缓存，空间片段在读取下一帧前脱离大父分配。压缩主路继续复用 `StageStore` 的RAM、设备或磁盘载体，并按安全块填充。旁路临时元数据在批次结束后清理，不随序列长度无限积累。此轮不对所有算子开放通用原地写入，也不默认同时保存每级完整输入输出。

资源准入仍保留原有基于完整逻辑形状的保守检查。局部执行能减少实际工作量，但特别大的输入仍可能先被全图工作集估计拒绝；本版本不通过修改逻辑shape或删除旧校验放行。物理执行的块预算、状态锁定和回退也不能替代这项准入检查。

## 正式性能复测

2026-10-29，在Ryzen 9 9950X、RTX 5070 Ti、Windows、Python 3.12.10及现有NumPy / CuPy环境串行复测。最终版本真实CINE共39次、通用流程共72次，均为每组3轮新进程，轮换顺序，测量前后源码哈希一致。汇总与每轮原值见 [可共享JSON](benchmarks/processor_0_9_3.json)。

### 原始CINE完整处理

同一10284帧、600×832、uint16输入，W=1001、τ=0、步长1，输出9284个标量。未强制清空OS文件缓存，测试前已读取过来源；不能当作磁盘冷读成绩。以下为完整任务中位数，包含来源、CSV及PNG / SVG，排除Python进程启动与导入。

| ROI均值流程 | 同源码兼容执行 | 优化执行 | 加速比 |
| --- | ---: | ---: | ---: |
| CPU | 37.60秒 | 7.31秒 | 5.14倍 |
| GPU标定、CPU配准、GPU后续 | 40.64秒 | 6.56秒 | 6.20倍 |
| 连续GPU | 9.37秒 | 4.21秒 | 2.22倍 |

这里的兼容组使用相同0.9.3源码和 `optimize=False`，也包含本次静态几何改进；不能把它称为完整0.9.2版本。此前39次实验中的0.9.2工作台CPU / 混合GPU / 连续GPU分别为46.80 / 63.00 / 9.28秒，两批实验分开保存。

本轮独立专用代码的CPU / GPU中位数仍为4.48 / 2.71秒。通用执行器已经明显接近，但没有达到专用实现耗时，也略高于提案的7秒 / 4秒工程目标。后续减少通用取样、中间数组与交付调度仍有空间，不能宣称已经达到硬件极限。

所有组保持10284次输入读取。优化路径的前序标定元素数从5133772800降到385526592，约7.51%；完整双路信号仍仅164544字节。连续GPU最终结果回传37次，新增小信号关联内核37次，替代原逐输出回传和28370次关联调用；混合GPU另有明确的CPU边界回传，不能把全任务总回传也写成37次。

ROI的24次正式试验共检查222816个有效输出，CPU优化组与原CPU输出逐值相等，全部组最大绝对误差2.22×10⁻¹⁶；全部9284条来源逐字节相等，CSV及图形导出核对通过。

### 最新单点流程

原配准后 `(0,0)` 单点流程的优化CPU / 混合GPU / 连续GPU三次中位数为3.50 / 4.00 / 3.93秒；本轮独立专用CPU / GPU为2.60 / 2.06秒。小信号的GPU初始化、调度和传输仍可能超过收益，不能依据显存空闲就认定GPU应更快。

该点两路信号全为0，9284个g²输出均为NaN。除核对139260个输出位置外，另采集最终版全部10284×2中间信号，与6次独立CPU / GPU运行逐值核对，每次20568个值一致。它用于性能及信号验证；有效g²精度由ROI案例和非零点回归共同验收。

## 验证证据与复测方法

定向验证已分别完成：

- 能力与执行计划15项，检查36模块覆盖、插件保守能力、LUT和均值滤波校验、左右暗场、空间尺度、依赖、实例顺序、设备、精度及指纹。
- 通用空间执行76项，覆盖CPU及HostDevice的优化开启 / 关闭对照，核对全部数值、dtype、有限性、坐标及来源；包括多ROI、点线截面、颜色、配准插值、Gaussian原边界、时间编辑、随机访问、嵌套状态、长分位窗口、旁路、非法输入、取消和缓存预算。
- 通用基准校验7项，防止漏查尾部数值、±Inf、轴、dtype和来源差异，并保证CPU / GPU使用相同科学参数和模块标识。

HostDevice仅验证调度和语义，不代表CUDA性能。最终完整 `pytest --require-cuda` 已通过716项、0跳过，覆盖真实CUDA、CPU、Web多进程与导出；CPU和GPU浏览器预览、处理、详情、阶段检查及导出闭环通过。GPU浏览器还核对了新增「执行优化与数据范围」区域。此前独立专用代码的耗时不作为本版本工作台已经达到的速度。

真实CINE复测保留原输入、参数、预算和完整数值 / 来源 / CSV / 图形导出。通用执行器基准另用同seed的内存合成数据，覆盖逐点变换加ROI、点提取、高斯邻域、时间编辑、任意线与完整图像控制，逐组新进程串行运行并轮换顺序。后者只测引擎构建、全部输出与来源及收尾，排除数据生成、磁盘解码、应用导出和验证，不能与完整应用耗时直接混比。
