# 0.8.4：大序列处理与 GPU 数据复用

本版围绕视频预览与数据处理，优先减少数万帧流程中的重复传输、重复窗口读取和重复统计。保留 0.8.3 工作台布局，CPU 完整可用；预览检查继续使用独立进程与资源份额。

## 使用

在「运行设置 → 统一资源预算」设置显存上限及默认设备。模块的「实例执行覆盖」可选择 CPU、自动或 GPU；留空继承工作台设置。安装方式沿用 [可选 CUDA 环境说明](RESULT_RESOURCE_GPU_0_8_0.md#gpu-支持范围)，需要与驱动匹配的 CuPy。

迁移电脑或安装 CuPy 后，在运行设置点击「重新检测」更新 GPU 状态；普通占用读取仍使用最近一次检测结果，不反复初始化设备。展开「运行环境」可以查看后台实际使用的 Python 路径、版本及程序位置。命令行自检与工作台必须使用同一支 Python；`start.cmd` 优先选择其所在项目目录里的 `.venv`，可能与在上级目录安装 CuPy 的环境不同。关闭浏览器不会停止 Python 后台，切换环境后需要停止原服务并重新启动。

- 自动模式：启动时检查 CUDA，不能使用时明确记录 CPU 回退原因。
- GPU 模式：缺少 CUDA 或模块能力时明确失败。执行中的计算错误、显存不足仍是失败，不会隐藏并改用 CPU 重跑。
- 原始数据解码与文件写入仍在 CPU。连续 GPU 节点直接传递设备数组，预览、输出保存、显式 CPU 节点和插件形成主机边界。
- 来源及 CPU 边界采用有界批量上传，每批最多 32 个样本；大帧自动缩小批次。检查流程一次读取一个样本；含跳帧抽样的流程不预读被跳过的样本。

## 支持范围

当前模块库的 **25 个内置模块均可接入设备处理链**。轻量节点有的只索引或传递设备数组；设备兼容不代表每个节点独立使用 GPU 都更快。模块公式、真实轴和逐模块设备声明见 [当前模块清单](MODULE_INVENTORY_CURRENT.md)。

| 模块组 | 0.8.4 行为 |
| --- | --- |
| 时间滑窗、合帧 | 均值 / 求和复用进出窗口并补偿累加，定期重建以控制误差；精确分位值复用环形窗口 |
| 时序统计 | 设备上逐样本归约，保留 T/Q 及应保留的双路 / 颜色分量；支持 min、max、均值、和、计数、总体方差、标准差及分位值 |
| 全域统计 | 按预算批量归约，保持既有全部数据 / 样本 / 时空范围；均值与方差用固定基线及合并 Welford 累积 |
| 分布统计 | 自动上下界扫描和多样本 bincount 在设备执行，输出强度箱的频数，不输出 TYX 强度矩阵 |
| 配准 | 坐标、插值权重与有效掩码复用；最近邻 / 双线性及边界与 CPU 相同 |
| 标定、曲线、增益 / 偏置、平滑等 | 固定 LUT 只上传一次，保持饱和、暗场、精度、颜色和双路规则 |
| ROI、取点、线 / 轴截面、颜色及通道选择 | 直接处理设备数组，真实形状继续向下游传递 |
| 参数传递、数据截流、时间裁剪 / 抽样 | 保持流程契约；需要参数或导出时读取相应值，主路继续使用设备数据 |
| g² 系数图及延迟曲线 | 原有设备算法衔接上游设备数据；保留负、零、正 τ 与有效配对规则 |

第三方插件、旧序列统计与旧空间编辑兼容实现仍走 CPU。CPU 节点显式出现在运行记录中，不隐式重排流程。

## 精确分位值与预算

窗口分位值仅写入新进入的样本。小窗口可保存在显存，较大窗口使用磁盘环形数组，按组件分块在设备求精确排序位置；CPU 也复用磁盘窗口。单条时间序列超过工作预算时明确报错。取消、异常和正常结束都清理临时文件。

全域分位值先流式建立临时磁盘数据。能放入预算的组件直接精确排序 / 选择；更长的单条序列使用有界的 8 轮字节位排序计数选择真实 float64 值，再做既有线性插值。不会用分箱近似、平均分位值或抽样替代。大型全域分位值可能受磁盘往返影响，不能保证 GPU 一定提速。

设备上传缓存和阶段缓存各占工作进程显存份额的 1/16，并有 LRU 上限。预检合计工作数组、保留窗口 / 配准 / 统计状态与缓存，另预留批处理和排序空间。现有任务与检查按 3:1 分配显存；设置过低时提示裁剪、提高预算或选择 CPU。

预算约束应用分配及 CuPy 内存池，不是整个进程或整块 GPU 的独占保证。解码、CUDA 上下文、库内部空间、驱动和其他程序仍会占用资源，实际显存不足会报告失败。

## 数值与来源

统计继续忽略非有限值，全无效时返回 NaN（计数为 0）；双路共同有效或独立有效规则保持原设置。方差为总体方差，默认 float64 计算；显式精度设置仍决定最终模块输出。整数输出继续沿用量化和裁剪规则。

CPU 和 GPU 并行归约的加法顺序可能不同，应按误差容限比较浮点结果。分位值、直方图边界、T/Q/P 轴、真实时间和贡献来源的含义不变。显示窗宽及色图不会进入算法输入。

运行记录保存版本、模块顺序、实际设备、回退原因、预算、窗口存储方式和精确统计方式。`device_execution` 记录数组边界上传批次、样本数、回传次数、缓存预算和峰值；这些计数不包含标量同步或 CuPy 内部操作，不能当作硬件性能计数器。

## 本版验收与限制

- 相关测试 121 项通过，2 项需要 CUDA 的测试因本机无 CuPy / CUDA 而跳过；13 项无关测试未运行，未执行全量回归。
- 新增专项覆盖 CPU / 主机数组设备适配器对照、万帧有界批处理、大基线小涨落方差、精确分位值、窗口复用、插值 / LUT、直方图边界、双向延迟、CPU 边界、取消及文件导出。
- 万帧用例处理 10000 个样本，313 批上传并只回传最终统计量，核对方差 8333333.25。这里验证调度和数值，没有测量 GPU 速度。
- 独立浏览器服务完成模拟 uint16 TIFF 的预览、滑窗 → 时序分位值 → 全域方差、数值导出及完整运行包导出。实际后端为自动回退 CPU，方差为 307496；无 JavaScript 错误。1600×1000 与 1024×768 截图已检查。
- 本机报告位于被忽略的 `.test-output/gpu-pipeline-1792238300/report.json`，同目录含截图和运行包。可用以下专项命令重新生成：

**本机没有完成 CUDA 真机数值及吞吐验证。** 主机数组适配器只能验证设备调度、边界和共享计算定义；正式评价提速需要在目标 GPU、真实帧尺寸 / 位深 / 窗口与显存预算下，分别记录解码、计算、传输、导出时间及 CPU / GPU 误差。没有给出未经测量的提速倍数。
