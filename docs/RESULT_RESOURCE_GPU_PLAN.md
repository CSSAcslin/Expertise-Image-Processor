# 结果管理、统一资源预算与 GPU 实现计划

日期：2026-10-13。主线仍为数据预览 → 模块处理 → 结果验证、导出和复用。

## 本轮交付

1. **结果管理**：统一列出已保存和试算结果，主输出及旁路仍共用结果预览；集中提供导出、作为下一阶段输入、改名和删除。删除区分移除工作区记录与清理本次运行文件，提前展示文件路径和依赖；仍被输入或运行引用的文件不得删除。导出完整运行包保留数值、映射、参数和来源，不经内存拼装。
2. **资源设置**：工作区级持久配置处理预算、预览缓存、计算缓存、显存预算和默认设备；试算、检查与正式运行保存同一资源快照。模块可继承设备或显式覆盖，实例内存只可收紧统一预算。可查看实际进程内存和缓存占用、清理空闲缓存。正式任务串行；从处理预算预留四分之一（最多 256 MiB）用于阶段检查，显存按任务 / 检查分配 3:1，保留运行期间的检查和原始预览。
3. **有限内存**：原始读取与预览缓存按统一配置；累积流程的工作数组与缓存一起核算。均值 / 合帧沿用逐样本累加；窗口精确分位值改为磁盘临时数组和分块计算，避免整窗口 RAM 堆叠。资源不足在计算前说明模块、需求和修复方式，不用显示降采样改变科学输入。
4. **GPU**：复用模块契约，提供强度 / 增益偏置、固定强度曲线、阈值、均值 / 高斯平滑、固定归一、灰度和 g² 的 CuPy 实现。CPU 完整保留，自动模式只在启动检查时回退；显式 GPU 不可用或模块不支持时清楚报错。记录每个实际计算模块设备与原因；CPU / GPU 保持精度、NaN 和双向延迟定义一致。GPU 为可选依赖，不自动修改用户系统运行环境。

## 验收

- 正式输出 → 预览 → 导出运行包 → 作为新输入 → 后续运行，数值和来源可验证。
- 删除任务 / 结果引用、删除磁盘文件、依赖阻止及越界路径保护。
- 配置重启持久化、快照一致、缓存释放、低预算窗口精确分位值与参考值一致。
- CPU 核心回归、可选 CUDA 数值对照；没有可用 CUDA 时报告硬件验证未完成。
- 独立服务和浏览器验证结果管理、资源面板以及常见桌面 / 小窗口布局。

## 边界

预算约束应用控制的数组和缓存，不承诺硬性限制 Python、解码库、操作系统文件页缓存及第三方插件的全部 RSS。单帧超过工作预算仍需裁剪或提高预算。暂不增加视频编码导出、远程计算、暂停恢复和空间位移扫描。
