# Web 工作台前端检查与完善

本轮目标：可靠导入真实数据，在原始坐标中预览和修改 ROI，验证处理结果，并将明确选中的结果继续用于下一阶段处理。

## 已确认方向

- 数据串联优先采用处理流程串联；正式输出可明确成为下一阶段输入，保留上游运行、来源、裁剪坐标和时间映射。
- ROI 管理方式及 UI 布局方向暂未收到选择。本轮沿用每个来源一个矩形 ROI、深色三栏，补齐编辑和收起面板；这两个方向可根据用户后续意见调整。

## 检查发现与执行顺序

1. 数据导入：区分文件与目录序列；校验真实路径；批量导入逐项反馈，保留成功项；增加筛选、全选、来源移除与完整属性查看。
2. 显示预览：输入与结果分别配置显示范围，显示目标明确；保留数据原值；修复延迟响应覆盖新状态和播放循环重入；对未知时间、显示降采样和缓存失效给出可理解的反馈。
3. ROI：原始像素坐标、严格边界、移动/八方向缩放、数值编辑、撤销恢复，切换来源不会误带另一来源的选区。管理策略按用户选择实施。
4. 处理串联：结果浏览保持原输入；“作为下一阶段输入”显式创建派生输入；清空上一阶段处理链避免重复处理；运行记录保存父运行、父来源、输入裁剪原点和时间来源。
5. UI：提高文字可读性，缩减无操作意义的说明，显示来源—处理—输出关系。布局方向按用户选择实施。
6. 验证：手工可核对的高位深数据、坏文件混合导入、连续快速定位、ROI 移动缩放边界、串联两次并重新打开、项目恢复、大/小窗口和实际浏览器。

## 保持的数值语义

- 预览 LUT、伽马和显示降采样不进入算法输入。
- ROI 为全帧执行算法后裁剪输出，滤波上下文保持完整。
- 视频按真实 PTS 定位；未知帧号不根据平均帧率估算。
- 派生输入的坐标从其当前数组左上角开始，原始坐标关系保存在来源链中；处理结果和原输入不会静默互换。
- 单次试算结果只存在缓存，下一阶段串联使用正式保存的输出，避免引用随时过期的数组。

## 本轮完成与验证

上述六项已落实。额外修复了图像序列末帧反复请求、显示直方图错误沿用窗宽轴、快速响应覆盖新来源及刷新丢失参数的问题。专注预览隐藏侧栏、显示设置和任务区，退出恢复原布局。

- 36 项数值及接口测试通过；两次正式串联的 uint16 裁剪、增益和偏置与手算数组一致，来源链在项目重新加载后仍可继续。
- 独立 Edge 浏览器覆盖混合失败导入、未知路径、序列间隔和末帧停止、快速定位/来源切换、ROI 编辑和原值统计、刷新、独立显示、正式结果再次输入及 1440×960 / 1024×768 布局；无前端脚本错误。
- 当前工作台升级采用本地维护快照保留来源、结果和已结束任务，原值缓存在重新定位时重建。

未扩展多 ROI、空间配准、文件拼接或时序/机器学习执行器；数据串联本轮采用用户确认的处理流程串联。
