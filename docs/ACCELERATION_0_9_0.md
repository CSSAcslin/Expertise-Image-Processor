# 0.9.0 运算加速与性能诊断

本轮围绕正式处理的读取、g² 累加、设备数据复用和结果交付优化，不改变模块顺序、ROI、时间配对或标准 g² 的定义。原数据预览沿用同一工作台，CPU 完整可用，GPU 可选。

## 运算实现

- **融合 g² GPU 运算**：真实 CuPy 使用专用 ElementwiseKernel，一次更新左右波动和、交叉乘积和及共同有效样本数；结果也由融合内核计算。保留 float64，关闭融合乘加优化，避免暗降精度；不吞掉内核编译或执行错误。NumPy 及主机设备适配器仍使用参考数组实现。
- **有界小信号批量**：空间元素不超过 4096 时，按任务、实例及显存预算选择最多 64 对样本；每像素按原样本顺序累加，不作并行求和或隐式合帧。暂存的小视图脱离可能持有的上游整幅图像，大图逐对融合，避免额外整窗堆叠。
- **固定中心复用**：g²(W) 和固定中心延迟扫描复用同一基准。单调扩大 W 复用累计量，不再每 256 个输出完整重读扩大后的窗口；缩窗、随机访问、变更延迟仍按真实配对更新或重建。滑动中心的周期重建保留。浮点累加历史可能改变，数值按容差核对，不承诺逐位一致。
- **减少无用工作**：零延迟从同一样本获取左右两路，主流程仅需 g² 时不再生成未使用的 count 数组；最近 256 个已读样本的帧引用可以复用，避免仅查询来源就重复解码。
- **固定上传分块**：最多 32 个样本组成对齐块。窗长向更小索引扩大时，可复用同一块，不再为每个新左侧样本重复上传相互重叠的向前块。原始 uint16 等按实际传输类型估算，不统一按 float64 放大。
- **按流程余量使用缓存**：在预估保留状态和工作数组之外，设备缓存容量最多使用计算进程显存预算的四分之一；余量不足时缩小。容量按需使用，不预占全部显存。正式处理与检查仍分配各自份额；检查只预取单个样本，含抽样跳步的流程继续保守预取。
- **多页 TIFF 句柄复用**：一个读取器持有一个数据句柄，复用页偏移索引，避免每读一页重新打开并遍历索引。禁用逐页对象缓存，图像仍按需读取；页偏移表随页数增长。读帧 / 关闭加锁，关闭释放文件句柄，来源修订检查保留。
- **减少进度通信**：正式流程保留首、末结果通知，中间最多每 0.2 秒通知一次；每个数值结果仍完整写出，取消检查不依赖进度通知。

CuPy 的 [自定义内核说明](https://docs.cupy.dev/en/stable/user_guide/kernel.html) 描述了显式输出、raw 索引及非连续输入的处理；[性能说明](https://docs.cupy.dev/en/stable/user_guide/performance.html) 解释了异步执行、初始化及编译成本。

## 查看实际耗时

任务详情新增默认收起的「运行耗时与吞吐」，每个来源分别显示准备、输入读取 / 解码、临时视频索引、CPU 模块、GPU 主机调度、上传 / 回传、来源映射、摘要统计、曲线图生成及输出写入。记录保存在 `run.json` 的 `results[].performance` 中，失败或取消也尽量保留已有统计；旧运行不补算。

主机分类采用互斥计时，嵌套耗时从外层扣除，总和对应这个来源在计算进程中的耗时，包含准备和输出，不含排队、进程启动和最终运行目录发布。GPU 异步执行可能在上传 / 回传处等待，**这些主机阶段不能单独解释为纯内核或纯 PCIe 传输时间**；纯 GPU 内核时间本轮未采集，保存为 `null`，不填零或估算值。

输入指标为读取次数及返回的解码数组字节，含视频建索引、临时索引重读、重复请求和读取器缓存命中，既不是唯一原始帧数，也不是磁盘物理流量。输出率按真实样本轴区分 T 样本、W 窗长、Q 延迟点与 N 记录。**每秒 50 个 W 结果不等于每秒读入 50 帧原视频。**

运行记录还保留每实例实际设备、`correlation_implementation`、上传次数 / 样本数、最大上传批次、关联更新调用 / 配对数、最大关联批次及缓存容量 / 峰值上界。这些是执行器调度计数，不是硬件利用率计数。

## 本机合成数据对照

对照旧版本 `dd17810`（0.8.6）与 0.9.0，使用同一 Python / 依赖、同种子合成 TIFF、同模块参数。机器为 Windows 11、Intel Core i7-12700K，Python 3.14.3、NumPy 2.4.6、tifffile 2026.6.1。仅测 CPU，未安装可用 CuPy / CUDA。

输入 769 帧 uint16，每帧 128×256，固定配准为左右各 128×128；τ=+1，固定中心，W=2…600、步长 2，共 300 个输出。资源为内存 2048 MiB、计算缓存 128 MiB。每流程各运行三次，每次启动独立进程，取正式处理函数耗时中位数，包含读取、计算、数值保存及应有的静态图形导出，排除子进程启动。系统文件缓存已热；不是冷盘或通用吞吐承诺。

| 正式流程 | 0.8.6 | 0.9.0 | 加速比 |
| --- | ---: | ---: | ---: |
| 双幅配准 → g²(W) 图像 | 1.455 秒 | 0.942 秒 | 1.54× |
| 双幅配准 → 取点 → g²(W) | 1.314 秒 | 0.885 秒 | 1.48× |
| 双幅配准 → g²(W) → 像素空间均值 | 1.493 秒 | 0.955 秒 | 1.56× |

三条流程在 W=2、302、600 按独立直接公式抽查，有限值掩码一致，最大绝对误差 2.22×10⁻¹⁶。完整摘要见 [CPU 基准记录](benchmarks/acceleration_0_9_0_cpu.json)。同次 TIFF 热缓存、零像素缓存的读取小测试，逐帧打开约 0.415 秒、复用句柄约 0.063 秒；这是读取环节的单次小测试，不能当成完整流程加速比。

点流程的一次运行中，曲线 PNG / SVG 生成约占 0.45 秒，明显多于 g² 的部分计算；这说明小结果也会有固定交付成本。关联后求均值仍需完整图像关联，不能为加速而静默移动该节点。内存 / 显存设置是上限，超出实际工作集需求后继续增加不保证收益。

## 在 GPU 电脑复测

在仓库根目录，使用**启动程序的同一 Python**，保持现有可用 CuPy 环境。关闭其他重负载任务后执行：

~~~powershell
.\.venv\Scripts\python.exe tools\benchmark_acceleration.py --backend both --repeats 3 --output-dir .test-output
~~~

工具生成独立合成数据与正式运行包，比较图像、关联前取点、关联后空间均值三流程，记录 CPU / GPU 实际设备、版本、预算、误差、来源耗时和包含启动的进程总耗时；不会读取或改变实验数据。无 CUDA 会明确跳过 GPU；选为 GPU 后发生编译 / 数值错误则报告失败。正式任务仍有各自 CUDA 上下文初始化成本，不能把这些结果宣称为纯内核基准。

可设置 `--frames`、`--height`、`--width`、`--window-max`、`--lag`、`--memory-mb` 和 `--gpu-mb`，尺寸为每幅宽高。工具限制合成输入及单个图像输出各不超过 256 MiB，合计数组不超过 1 GiB，最多重复十次。默认在临时目录生成唯一文件夹；指定输出目录也只新增唯一文件夹，结束打印 `report.json` 路径。

已有旧版本源码时，可用 `--source-root <旧版本的src目录>` 对照；工具不自动切换 Git、下载版本或修改另一个源码目录。升级后查看任务详情的实际设备；全局 GPU 不会覆盖实例中明确指定的 CPU。

## 验证与当前限制

CPU / API 回归覆盖 g² 正负延迟、无效值、极小涨落、固定与随机窗口、超过 256 个 W 的复用、预算、来源、保存与取消。真实 CuPy 专项对照另覆盖标量 / 图像、非连续批量、样本移除和融合结果。首次发布时的 i7-12700K 环境缺少 CUDA，硬件测试跳过；2026-10-27 在另一台 RTX 5070 Ti 电脑补齐了真机数值、全部可见模块、浏览器及同机性能验证，详见 [GPU 落地说明](GPU_DEPLOYMENT.md)。

浏览器专项验证一次正式 W 流程、窄任务栏单位、默认收起耗时区、数值记录和下载，以及桌面 / 小窗口；普通预览不触发额外计算。读取、输出及外部插件仍可能限制整体速度。原有完整数值、PNG / SVG 导出继续保留，本轮不默认取消导出或降低精度来缩短计时。
