# 延迟扫描批量执行与实测

日期：2026-10-29。版本：0.9.4。承接 [纯流程对照及优化方案](DELAY_SCAN_OPTIMIZATION_PLAN.md)，针对固定中心g²(τ)扫描的逐样本调度、重复小数组复制与来源时间树重建进行正式后端改造。

原3001点延迟扫描完整复跑，CPU三轮中位数 **2.89秒**，原混合GPU设置 **3.74秒**，均达到首轮≤5秒目标。全部3001个float64结果逐位一致，来源文件字节一致。用户原0.9.3 GPU单次记录为1637.97秒，较该历史记录约438倍；这不是旧新版都重复三轮的严格加速比。

## 实际改变

### 连续信号直接交接

`StageStore.get_range`提供已就绪的连续RAM／设备视图，按缺失物理块填充，不再为关联的每一对样本构造小数组。RAM视图只读，主存储仍可继续填充；磁盘读取须满足明确的暂存额度。取消、短读、部分就绪和前序缓存释放沿用原保护。

引擎通过`_stored_range`访问实际载体，禁止隐式跨设备转换。前序GPU标定、CPU配准等仍按实例设置执行，最后的紧凑双路信号作为关联直接输入。原任务双路主路数组仅810464字节，本例1251次连续范围请求即可准备全部必要信号。

### 按多个τ产出关联结果

新增公共`LagScanBlocks`执行适配器，复用流程契约和已规划阶段存储。CPU使用按样本顺序的float64累计，GPU按Q及分量分配线程，在每个线程中保留原W顺序、共同有效样本、固定中心基准及最少样本／均值规则，禁FMA。

一次最多输出256个Q，另受任务、模块、显存、暂存和单次配对工作量约束。本例为12个输出块，GPU关联发射从474158次降为12次，仍计算30,013,001对样本。只准备左窗、各有符号右窗和中心的区间并集，不主动填充不参与运算的时间间隙；物理块边缘可能多读。

Q试算本来就输出完整曲线，现在可使用与正式运行相同的批量路径；单样本T试算和阶段检查仍保持按需访问。随机及重复Q请求正确，累计状态不会被其他Q污染。关联输出精度及后续逐点模块各自执行，显式CPU／GPU切换、旁路及原模块顺序保留。

### 来源时间按依赖复用

新增`LagTimeIndex`，缓存直接上游的真实时间及已知标记，对各τ使用有界数组差分和归约。固定τ的T／W扫描继续使用原增量时间索引。

简单时间裁剪、抽样及时间透传前缀可以直接批量读取CINE的逐帧TIME64或已有时间索引。合帧、平滑、复杂时间映射、临时索引和自定义样本来源仍通过原`ref`接口生成直接上游时间，完整保留贡献范围。`None`与已存在但非有限的时间分别处理，非有限／溢出按原顺序回退，不用平均fps推算。

密集惰性时间表、固定数量LRU时间页和极小预算的逐项路径共用接口。缓存、暂存与批量提供器的峰值均计入来源预算。本例仅取得40001个必要窗口样本的时间，每个一次，中心结果引用另行保留；来源数组实际占796569字节，保守峰值预留1147628字节，低于8MiB预算。

### 交付和观察

Q块统一经过既有后处理及主机交接，再写逐Q数值、来源和CSV。完整来源二次修订校验、旁路完成状态、未完成输出保护和原子发布仍由原正式处理流程执行。

任务详情增加τ批量输出、实际配对数、GPU发射数、连续信号块和来源时间读取数。新Q内核纳入既有有界CUDA事件计时。主机提交含等待，采样事件区间仍不冒充全部GPU内核活动时间。

## 完整任务复测

同一Atip53000fps.cine，50654帧、112×832、uint16。流程为全时段、线性4095标定、固定最近邻配准、对应点(x=46,y=44)、固定中心g²(τ)。W=10001，中心零基10326，τ=0～30000／步长10，共3001Q。硬件为Ryzen 9 9950X和RTX 5070 Ti。

每类CPU与GPU各3轮，新子进程串行轮换，保留首次进程内CUDA准备和编译／磁盘缓存加载。文件系统缓存温热，未清空CuPy磁盘缓存。完整计时包含读取、前处理、计算、来源、CSV／图形、来源复核和正式发布，结果核对在计时之外。各阶段中位数不能相加代替某一轮总时间。

与独立原型的1.72／1.76秒仍有距离：正式模块前处理、原混合设备边界、任务及来源保护都保留。当前主要时间已转移到读取和前序准备，而不是延迟关联和来源树。

GPU共12次Q内核调用，采到7次、首调排除1次、按现有采样策略未抽取4次。三轮已采事件区间累计各约17毫秒，不按比例外推，也不与独立原型一次全Q内核的2.45毫秒直接相比。正式路径分块更小，且计时覆盖范围不同。

## 正确性与回归

- 完整Q的6轮各3001值均与原任务逐位一致，有限性与dtype完全一致，最大绝对误差0。来源、CSV及输出契约全部通过核对。
- 固定τ的T序列另完整复跑6轮，每轮40654值逐位一致，来源字节相同；CPU／原混合GPU中位数5.74／6.69秒。原0.9.3该GPU单次记录7.46秒，没有观察到本次改造造成的性能倒退。
- 固定τ的W扫描另复跑6轮，每轮3301值全部通过；CPU逐位一致，混合GPU最大绝对误差2.22×10⁻¹⁶，所有来源字节相同。CPU／混合GPU中位数7.24／8.05秒；该历史任务来自0.9.1，不作为0.9.3到0.9.4的独立性能归因。
- 完整测试 **856项通过，0跳过**，包含真实CUDA、正／零／负延迟、随机及重复Q、偶数W、小向量、未知／非有限时间、时序编辑、试算、后处理精度、混合设备、预算与取消。

## 适用边界

本轮Q数值批量优先使用直接输入为已驻留float64双路紧凑信号的流程，包括点、区域信号及预算允许的小向量／小图。组件数最多4096，W最多65536，单次W×组件×Q块工作量最多8388608；块大小还会按各层预算收紧。

没有直接主路检查点、检查点需精度转换、检查点在磁盘、后续模块不能按块转发、组件或窗口工作量过大时，保留正确的按需数值路径，并记录具体原因。来源时间优化仍可独立生效。未知插件与复杂上游依赖不会为进入快路径而被绕过；真实执行出错时直接报告，不静默换路径重算。

因此，本轮没有宣称所有空间大图或任意插件都达到本例速度。模块仍可编辑、替换和排序，预览及处理继续共用数据、时间、坐标与结果模型。

## 复现

```powershell
.venv\Scripts\python.exe tools/benchmark_direct_lag_scan.py --phase app-full --repeats 3
.venv\Scripts\python.exe -m pytest -q --require-cuda --basetemp .test-output/q94check

```

基准默认复放原完整Q任务，`--phase app`仍为31Q诊断，`--phase direct`仍为独立代码，三种计时不得混用。CPU测试策略将全部实例明确置CPU；混合GPU策略保留原实例设备设置。
