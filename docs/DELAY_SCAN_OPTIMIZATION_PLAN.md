# 延迟扫描纯流程对照与优化方案

日期：2026-10-29。状态：方案已在0.9.4实施，正式CPU／原混合GPU完整任务三轮中位数为2.89／3.74秒，详见 [实施与验收](DELAY_SCAN_0_9_4.md)。以下保留独立原型依据及原工程目标；对应功能为固定中心的g²(τ)延迟扫描，输出轴是Q。

同一数据和全部3001个延迟，独立纯流程已经做到 CPU **1.72秒**、GPU关联版 **1.76秒**，均包含读取、计算、真实时间来源记录及CSV、PNG、SVG导出。原程序本次GPU运行记录为 **1637.97秒**。数值逐位相同，来源与CSV文件字节一致。下一轮应优先消除逐样本的小数组访问、复制和来源时间树重建，将本例正式程序完整耗时中位数 **≤5秒** 作为首轮验收目标。

这里的1.72／1.76秒是实测可达到的参照速度，并非严格的理论极限；约930倍是历史单次GPU运行与新专用GPU关联流程的差距，不能承诺正式程序直接获得相同倍数。

## 完整运算能达到的速度

以下独立代码列为3轮中位数。原程序完整GPU列来自用户已完成的单次任务，未再次运行27分钟的完整基线。

| 测量 | 程序原GPU记录 | 独立CPU | 独立GPU关联 |
| --- | ---: | ---: | ---: |
| 全部3001个Q完整耗时 | 1637.968秒 | **1.716秒** | **1.761秒** |
| 原程序GPU提交及相关等待 | 1152.272秒 | — | — |
| 独立关联计算，含主机调用与完成等待 | — | 0.2645秒 | 0.00363秒 |
| 真实时间配对摘要 | 包含于482.044秒来源阶段 | 0.0462秒 | 0.0470秒 |
| CINE读取 | 2.004秒 | 0.978秒 | 0.994秒 |

| GPU进程首次准备 | 包含于setup | — | 0.264秒 |
| GPU首次编译或缓存加载 | 包含于setup／首次调用 | — | 0.031秒 |

阶段中位数来自各自的分布，不能相加冒充某一轮总时间。读取差异还包含测量调用与访问路径差异，不能全算成磁盘性能提升。

预分配输入、延迟和输出数组，完成编译和预热后，完整3001Q一次内核发射的CUDA事件区间为 **2.454毫秒**；未做采样外推。该区间与含分配、延迟上传的3.63毫秒主机调用，以及1.761秒完整流程是三个口径。事件区间不等同于Nsight逐内核活动时间。

GPU完整耗时与CPU接近，是因为读取和交付已成为主体，约0.26秒CUDA准备抵消了CPU约0.26秒关联计算。后端优化应让真正的关联工作高效执行，完整任务是否更快继续实测。

## 当前程序具体慢在哪里

另外在当前程序上保持同一W、固定中心与真实配对范围，选取原来的31个延迟：0、1000、…、30000；CPU／原混合GPU各独立跑3轮。输出逐值相同，设备实际执行策略、契约和来源也核对通过。

| 31Q诊断 | 当前CPU | 当前原混合GPU |
| --- | ---: | ---: |
| 完整耗时中位数 | 9.589秒 | 14.966秒 |
| CPU运算 | 3.813秒 | 0.056秒 |
| GPU提交及相关等待 | 0 | 8.414秒 |
| 来源阶段 | 3.832秒 | 3.811秒 |

这组只用于定位开销，不能乘比例外推完整CPU或GPU耗时。

### 强度运算仍通过逐样本小对象调度

`SequenceEngine.correlate`在τ变化时重新建立累计状态，本身符合不同τ需要不同配对的定义。但每次重新累计仍经`_add_correlation_pairs`逐对取值：两个很小的CuPy数组视图被复制，拆左右标量，再堆成最多64对的小批次。

原完整任务因此发生约6000万次紧凑信号缓存访问、471157次`add_many`，加上3001次结果内核，共474158次融合调用。缓存已经命中，这些访问并不是反复解码原图；继续扩大缓存无法消除逐样本对象、复制和调度成本。

独立9Q调用分析实际观察到170017次`detached_pair`、2826次`stack`，而1413次`add_many`累计调用时间约0.031秒。该分析包含插桩开销，只用来验证调用结构，不参与性能中位数。

CPU也逐对进入数组运算。独立实现保持同样的30,013,001对和累计顺序，但由NumPy／CUDA内部完成，主机只按τ或Q块调度。

### 来源时间树在每个τ下重新构造

现有`WindowTimeIndex`能复用固定τ下平移或扩大的窗口。τ改变后，3001个窗口都重新对10001个配对逐项更新多层树节点，并反复调用来源字典接口。对固定中心Q扫描，该树没有得到增量收益，却付出了约O(QW log W)的维护代价。

独立来源代码仍读取每个参与样本的真实时间、计算每个配对差值，保留均值、最小、最大和已知数。改用有界数组差分与归约后是O(QW)，每个窗口暂存最多170017字节，本例全部时间数组及存在标记约455886字节。完整3001Q摘要约0.047秒，内容与原记录相同。

## 正式后端改造方案

本轮应扩展已有通用执行计划和关联模块，避免新增只识别这条流程的隐藏算法。原模块仍是配置、顺序、精度、设备及语义的唯一事实来源。用户继续在同一工作流中预览数据、设置模块、试算、正式运行和导出结果。

### 第一步提供连续信号块访问

为阶段存储增加有界连续范围与索引区间访问，返回真实dtype、轴、设备、起点、就绪区间及生命周期。已驻留的紧凑双路信号直接提供切片，不再逐样本`get`、复制、标量索引及`stack`。本例完整双路float64数组只有810464字节，适合直接作为关联输入。

CPU RAM、GPU驻留和磁盘阶段均通过同一访问契约提供数据。磁盘或预算不足时只读取并压紧当前块；取消或失败不能发布半就绪块。读者和旁路仍在使用的缓冲区不得覆盖，独占小结果接管后及时释放前序缓存。块与暂存都计入任务、模块和设备预算。

前序模块仍沿既有范围执行器运行：例如原实例指定GPU标定、CPU配准，就按该顺序批量交接，不能为了接近独立代码而改写实例设备或精度。未知插件可用原实现生成其规范输出，后续满足契约的紧凑关联阶段再优化。

### 第二步批量计算多个延迟

在关联公共数值层加入固定中心Q批量路径，由现有`correlation_curve`调用；不把Q当作连续时间T，也不套用固定τ的移动窗口递推。

- CPU首批覆盖标量及预算内小向量，按τ读取连续左右窗口，使用保持样本顺序的float64累计。共同有效样本同时决定左右均值及交叉项。
- GPU将一个Q或Q×分量分配给独立线程，按原顺序遍历W，批量写入g²及所需计数。禁FMA，不改为时间并行归约。
- 原型一次计算3001个Q；生产先按64～256个Q分块，限制单次工作量、暂存和取消延迟。本例256Q约12次关联发射，取代数十万次小提交；最终块长由实测和预算决定。
- 大W需要分段时，直接携带累计状态继续原样本顺序，不能把多个块分别求和再相加来改变舍入规则。不能满足预算／响应约束时明确回退。
- 预览阶段检查、试算与正式运行共用该数值实现。随机Q顺序、重复访问和负τ必须正确；后处理、参数绑定、截流和来源节点仍保留原顺序及语义。

先覆盖现有紧凑标量、点、区域信号和小向量Q扫描，再在预算与验证允许时扩展小空间图；大图继续使用合适的有界路径。空间逐像素g²的平均与先取区域总强度再算g²继续区分。固定τ的T输出和固定τ的W扫描保留各自状态策略，共用新的信号块访问，防止性能倒退。

### 第三步按时间依赖批量构造来源摘要

从直接上游的时间契约建立真实时间数组与“已知”标记，缓存受现有来源预算约束。固定中心Q扫描逐τ做窗口差分、计数与极值归约，不为每个τ重建时间树。小批Q与数值输出按相同坐标交付。

来源字段、贡献范围、模块实例和坐标映射继续完整保留。时间抽样、合帧和平滑必须先生成直接上游的真实时间与贡献描述；不能用源帧索引、平均fps或单个中心时间替代配对时间。

`None`、非有限时间、非单调时间分别保留当前含义；时间已知数与强度共同有效样本数是不同统计。标准数组路径不适用或预算不足时使用按区间去重的有界时间块；复杂未声明时间依赖则保留正确路径并记录原因。固定τ滑窗仍可使用增量时间索引。

### 第四步交付与计时按输出块组织

数值、来源摘要和CPU交付使用同一Q块，批量回传及写入；保留逐Q来源索引、CSV行和断点状态。只有数值、来源、全部旁路及来源二次修订校验成功后才发布正式结果。任务记录继续保存完整模块清单、参数、输入修订和输出语义。

任务详情新增Q执行策略及回退原因、信号块请求、逐样本访问数、Q块数、GPU发射数、来源数组与暂存峰值。主机读取、提交、传输、来源和写出继续互斥计时；GPU增加新Q内核的事件覆盖与首次准备说明，不能把提交耗时标成内核耗时。

## 验收目标与实施顺序

优先顺序为连续信号块访问、CPU／GPU Q批量计算、来源摘要批量化，最后连接块交付与任务详情。前三项共同决定完整提速；只优化GPU内核仍会剩下数百秒来源耗时。

| 验收项 | 本例首轮工程目标 |
| --- | --- |
| 正式完整流程 | CPU全CPU／GPU原混合设备分别3轮，新worker串行，完整3001Q中位数各≤5秒 |
| CPU关联数值阶段 | ≤0.5秒 |
| GPU关联提交至完成 | ≤0.05秒；CUDA首次准备仍计入完整流程总时间 |
| 来源时间摘要 | ≤0.2秒，全部记录仍生成并验证 |
| 来源读取与前序计算 | 最多原40032帧，每个必要前序样本只计算一次 |
| 精度与可追溯性 | 本例全部3001值以逐位相等为目标；一般CPU／GPU严格容差2×10⁻¹³，NaN与有效计数一致；来源整数、范围、极值精确，平均时差允许≤10⁻¹²秒舍入差 |

以上是下一版正式程序的验收目标，当前程序仍为0.9.3。本例完整运行争取进一步接近2～3秒，但正式模块执行、设备边界和交付工作都必须纳入测量。

回归矩阵覆盖正／零／负τ、非对称双路信号、显式与自动中心、不规则延迟、零均值与小波动、NaN／Inf、不同min_samples、非均匀及缺失时间、前序时序编辑、ROI／点／向量、CPU／GPU／混合边界、主机／设备／磁盘存储、预算不足、取消和失败发布。再复测固定τ的T流程与W扫描，确认旧优化保持有效。
