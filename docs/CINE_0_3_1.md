# 0.3.1：CINE 导入与帧位显示

围绕“视频预览 → ROI / 算法 → 验证导出 → 下一阶段输入”接入 CINE，不另建处理系统。实际验证样本为 `F:\Data-test\Test1\22741_1_4.cine`：15,201,368,592 字节、370,801 帧、256×128、100,000 fps 元信息、10 位 Packed 灰度，包含逐帧时间记录。

## 读取与数值边界

适配器依据 Vision Research 的 [Cine File Format（release 705）](https://phantomhighspeed.my.salesforce-sites.com/servlet/fileField?id=0BE1N000000kD2i)，使用文件帧偏移表、TIME64 和灰度像素布局。支持 v0/v1、8 / 16 位容器，以及保存值为 10 位的 Packed10；解码结果为 uint8 / uint16，保留码值。正常灰度行对齐与方向、Packed 行方向分别处理。

不自动执行相机 LUT 线性化、黑白参考校正、显示翻转或伽马。当前版本明确拒绝 Bayer / RGB、CCI 和需要扩展到其他有效位深的 Packed 变体；不承诺支持任意 CINE。用户的 Packed10 样本已验证，其他布局由小型人工构造文件覆盖。

只把偏移与逐帧时间表放入内存，像素通过随机文件读取逐帧解码；不复制整个 CINE，也不通过普通视频解码器降到 8 位。持久索引与时间表预算 128 MiB，单帧编码长度上限 256 MiB；读取检查结构范围、帧偏移、时间顺序、注释和像素长度。

## 位置的三种含义

| 显示 / 记录 | 含义 | 本样本示例 |
| --- | --- | --- |
| 文件帧号 | 从 1 开始的精确文件位置；内部索引从 0 开始 | 第 211742 帧，内部索引 211741 |
| 文件时间 | 本帧 TIME64 减文件首帧 TIME64，单位秒 | 2.1174100004136562 s |
| 采集源帧 / 触发时间差 | 保存的采集帧号；本帧时间减触发时刻 | 采集帧 0；触发后约 1.553446 µs |

采集帧 0 不必恰好等于触发时间差 0，两者均按文件记录展示。TIME64 的低位标志在数值转换前清除；先用整数时间差，再转换为相对秒数，避免 Unix 大时间值浮点减法损失高速帧精度。供帧身份比较的 `pts` 是相对首帧的整数 TIME64 tick，不是绝对 Unix tick。

Web 默认以精确帧号定位 CINE，可切换时间。时间输入保留实际返回值，底栏显示微秒精度，完整值可悬停查看。时间定位返回首个不早于目标时刻的帧，尾部钳制到末帧。缺少时间表时保留精确索引，禁用时间定位与按秒的处理范围；不利用相机帧率补造时间戳。常规视频保持真实 PTS 定位，未知帧号仍显示未知。

原来的固定时间轴提示已替换为动态位置；精确数据有“当前帧 / 总帧数”，CINE 另显示采集帧与触发差。定位过程中合并拖动请求，手动输入与处理按钮等待当前定位完成，避免旧请求覆盖新输入或处理尚未呈现的位置。较小窗口缩短长提示，完整含义仍可悬停查看。

## 处理和导出

当前帧、全数据与半开时间范围使用同一读取器。ROI 保持全帧计算后裁剪的既有语义，插件接收保存码值，不接收显示 PNG。正式输出沿用 TIFF / CSV / JSON，不写回 CINE。

CSV 和 TIFF 元信息新增 `source_frame_number`、`trigger_time_seconds`；既有 `source_frame` 为当前输入的零基索引，`time_seconds` 为输入文件相对时间。结果作为下一阶段输入时，保存原采集帧号与触发时间差，并沿用来源链；新的数组索引属于输出序列。旧记录没有新字段时按缺失处理，兼容 0.3.0 项目与输出。
