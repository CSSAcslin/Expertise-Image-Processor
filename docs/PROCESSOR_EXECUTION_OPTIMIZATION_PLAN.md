# 模块化处理流执行优化方案

日期：2026-10-29。状态：0.9.3已将本方案扩展为跨模块的范围执行、批量交接、静态几何及小信号连续输出；实际实施范围与验收见 [0.9.3执行说明](PROCESSOR_EXECUTION_0_9_3.md)。下文保留原提案及其工程目标，不能将目标视为实测。依据为 [39次 CPU 与 GPU 独立对照](DIRECT_FLOW_COMPARISON_0_9_2.md)，承接 [第一轮运算时间优化](EXECUTION_TIME_OPTIMIZATION_PLAN.md)。

建议保留可编辑模块流程，由后端将其编译成按所需数据范围、设备和预算执行的计划。重点是减少实际处理的像素、重复构造的静态数据、短小 GPU 调用和跨设备往返。模块顺序、参数、数值定义、预览入口和来源记录继续由现有流程决定。

这一轮主要改善正式处理和试算速度；阶段检查使用相同模块运算与范围规则，普通视频播放继续按需读取。原始数据与处理结果仍可独立查看、对比和导出。

## 实测依据

同一 CINE，10284帧、600×832、uint16，g² 使用 W=1001、τ=0、步长1，输出9284个 float64 标量。各组串行运行3次，保留完整来源、CSV、PNG及SVG，以下为完整处理耗时中位数。

| 流程与设备 | 工作台 | 独立专用实现 | 对规划的启示 |
| --- | ---: | ---: | --- |
| ROI均值 CPU | 46.80秒 | 4.61秒 | 减少上游全图浮点运算最有价值 |
| ROI均值连续 GPU | 9.28秒 | 2.71秒 | 按范围批量预处理，再批量计算小信号 |
| 最新单点 CPU | 49.54秒 | 2.58秒 | 点采样无需先生成完整标定、配准大图 |
| 最新单点连续 GPU | 8.68秒 | 2.02秒 | 小信号的调度与同步成本占比较高 |

移除模块执行器、但继续处理完整图像的独立 CPU 实现仍需46.08秒，连续 GPU 为8.77秒。因此，专用代码的全部收益不能归为模块函数调用开销。混合设备的调度差异更大，也不能用其差值估算纯框架开销。

ROI专用路径每帧只标定37488个像素，约为原499200像素的7.51%；仍完整解码同一 CINE。工作台已做到前序阶段每帧计算一次，双路小信号主路仅164544字节，来源映射约0.25秒。继续增加缓存或压缩来源记录已经不是本例的主要提速方向。

连续 GPU 仍有28370次融合 g² 调用和9284次标量回传。原 GPU 设置中的配准实例明确使用 CPU，ROI混合组为63.00秒，最新单点混合组为65.40秒，存在大图往返与同步等待。

ROI案例的9284个输出均有效，24轮对照最大绝对误差为2.22×10⁻¹⁶。最新单点的两路输入均为0、输出全为NaN；该组已额外核对全部中间信号，并用非零点测试验证算法，但不能用它单独验收有效 g² 数值精度。

## 从模块流程生成执行计划

增加一层由现有模块实例和数据契约派生的执行计划，记录每个实例需要的输入范围、运行设备、批量方式、输出载体及使用者。首次实现为明确的规划规则和执行适配器，无需引入新的编译器依赖。

| 层次 | 职责 |
| --- | --- |
| 模块流程 | 继续作为顺序、参数、版本、启停、目标通道和科学含义的唯一事实来源 |
| 执行计划 | 合成所需空间与时间范围，预编译固定索引，安排批量、保存点、设备传输与释放 |
| 数值实现 | 使用模块的标准运算及共享 CPU / GPU 数值原语；优化路径与兼容路径持续对照 |
| 来源与交付 | 保留全部逻辑实例、真实时间和坐标、贡献来源、旁路、正式与试算状态 |

若一个批量执行单元覆盖多个模块，运行记录仍逐一保留原实例，并额外记录其对应的物理执行单元。阶段检查请求到哪个节点，就以该节点作为消费终点重新规划；不能把只供最终 ROI 使用的局部数组冒充完整中间图。

初版在任务内缓存计划与静态索引。来源修订、模块版本与参数、输入契约、精度、设备或绑定依赖变化时失效。未知能力的插件沿兼容路径执行，已知可优化的后续片段仍可单独规划。

局部数据缓存必须额外包含请求范围、布局及计划版本，不能沿用只有阶段和样本号的缓存键，否则完整阶段检查可能误取局部结果。先完成完整逻辑契约和参数校验，再估算物理执行范围的峰值；不能通过篡改逻辑shape绕过资源检查。

### 模块需要声明的执行能力

在现有轴、类型和参数契约之外，为参加优化的内置模块补充以下能力：

- 从指定输出范围推导必要输入范围，包含坐标变换、空间邻域和时间上下文。
- 是否逐元素、逐样本或依赖全源统计，是否有副作用、动态状态及全输入校验。
- 可用的单样本和批量实现，输出 dtype、舍入与累计规则。
- 输出是否与输入共享底层分配、是否可接收独占缓冲区，以及暂存需求。

这些能力按模块及参数条件声明，不能依据“中间模块”或“修饰模块”的分类推断。初版不要求所有模块具备优化能力，也不把独立实验中的固定流程硬编码为新的工作模式。

## 优先优化所需像素范围

从所有真实消费者反向推导所需范围，再按原模块顺序向前计算。例如最终仅需要配准后的 ROI，就先将该 ROI 映射为左右传感器采样位置，在这些位置执行既有标定、配准、ROI和均值。保留范围中的每个像素仍先标定，随后配准与归约。

当前流程的推荐执行方式是：

```text
完整读取当前原始帧
  → 取得下游所需的左右传感器区域
  → 按原顺序完成这些像素的标定与固定配准
  → ROI结果或点值接管当前数据
  → 若需要均值，按原有效值规则归约
  → 保留完整双路小信号和来源索引
  → 分批计算g²并交付输出
```

第一批支持已实测的固定逐像素线性标定、固定最近邻配准、ROI裁剪或点提取、主路空间均值。先覆盖本例无LUT、两路零暗场、整数偏移、无镜像及既有精度参数，再逐项扩展其他合法配置。参数不满足已验证条件时，保留兼容实现并记录原因。

边界必须同时纳入计划：

| 情形 | 执行规则 |
| --- | --- |
| 多个点、ROI或旁路 | 合并全部消费者的需求；初版不能安全合并时，在该处保留完整阶段输出 |
| ROI前有完整图像截流导出 | 导出所需完整范围不能被最终ROI裁掉 |
| 全图统计、自动尺度、参数绑定 | 先按原定义完成统计或绑定；不能改成ROI统计，也不能删掉依赖 |
| 平滑或双线性插值 | 后续扩展时携带真实邻域、权重和原图边界；不能把ROI边缘当成原图边缘 |
| LUT或其他全输入数据校验 | 保留原校验范围；初版必要时拒绝前推，不能隐藏ROI外原本会触发的错误 |
| 插件、动态配准或未知依赖 | 在能力未声明前停止需求前推，沿已验证路径执行 |
| 非线性、有效值规则与精度转换 | 保持每节点的运算、舍入及掩码；不能将“先标定再平均”改成“先平均再标定” |

两路暗场不同时，配准前标定按传感器中线选择偏置，不能直接套用最终左右输出通道的偏置。扩展该参数须单独验证，首批不通过代数化简跳过实际模块运算。

空间归约紧凑化可能影响求和顺序。优先复用相同遍历和归约规则，CPU本例以逐值相等为目标，CPU / GPU用既定严格容差核对全部结果；不能通过放宽容差掩盖科学定义变化。

## 预编译CPU几何并减少中间分配

固定配准的采样索引、有效掩码和插值权重只随参数、形状及所需范围变化，应构造一次并复用。当前 `Geometry.apply` 每帧还在做坐标类型转换和 `clip`，且存在完整左右图复制及 `stack`。

先独立优化这些静态部分，即使某条流程无法缩小空间范围，也能受益。最近邻缓存整数索引与掩码；双线性缓存四组采样索引和权重，保留原来的零权重、无效值与边界规则。批量写入预算内预分配的输出或共享数值原语，避免为每个节点重复创建完整数组。

局部规划使用现有轴向量共同范围计算，再仅为请求域生成采样索引；点提取不应先构造完整二维坐标网格。静态索引和权重同样计入预算。

裁剪与归约后的结果成为当前主路数据。独占且 dtype、舍入与依赖允许时复用缓冲区；有共享预览、旁路、只读缓存或异步设备消费者时，最后一个使用者结束前不能覆盖或释放。小ROI视图若仍持有整张大图，应压紧保留部分，再释放旧底层分配。

本例不强制保存完整ROI序列。ROI紧接均值且无其他消费者时，逐块产生均值后直接释放ROI；若有后续消费者需要ROI，则根据其真实用途决定完整驻留、分块或磁盘保存。原始文件与可重新读取的来源记录继续保留。

## GPU按计算规模批量执行

### 前序模块使用真正的批量运算

现有按32帧上传不等于已经按32帧执行全部模块。增加明确的批量入口，将连续同设备、可批量的标定、几何、ROI及空间归约在一块内按逻辑顺序完成，减少逐帧 Python 与 GPU 调度。样本批量维度是执行细节，不能进入公开轴模型或被当作时间合帧。

块大小由主机预算、显存预算、实例限制和实际暂存量共同决定。峰值包含输入、输出、索引、有效掩码、归约暂存、传输缓冲和仍在使用的状态。先测16、32、64、128等块大小，选择有界且有收益的范围；预算不足时缩块，不按显存容量盲目扩批。

### 小信号关联批量产出

对本例10284×2的小信号，继续保留完整设备信号，新增可连续产生一批输出的 g² 执行入口。每批结束后批量回传数值，主机仍逐条生成相应来源和CSV。

批内按既定窗口顺序滚动，批间传递 float64 状态；周期重建按全局输出序号每256个输出执行，不能因切块重新计数。保留共同有效样本、低均值判定、输出 dtype及当前舍入约束，不以并行前缀和替代已验证累计。

独立代码用一次串行内核完成小信号，为减少调用提供了依据。生产版优先采用可取消的有界输出批次，不能将这一单线程策略直接用于大图。空间系数图按像素并行并受状态预算约束，Q扫描和W扫描分别遵守各自的布局与增量规则；未覆盖的情形保留原关联执行器。

首批批量关联覆盖本次固定τ、顺序输出的小信号。扩展到正负τ、多个延迟、W扫描和随机访问时分别验证；随机跳转、缩窗或反向访问须正确重建，不复用不适用状态。

Q扫描变更延迟时使用相应独立状态；固定中心单调扩大W沿用当前左侧新增、右侧新增的扩展顺序，原路径没有256输出周期重建，不能机械套用滑动T规则。首期这两类仍走兼容实现。

取消检查放在解码、前序块和关联输出块之间。实测并约束最大单块耗时，初步以常规块间取消响应不超过1秒为目标；不能用整个长任务的一次不可中断内核换取低调度次数。

### 尊重显式设备边界

CPU配准实例继续在CPU执行。GPU标定到CPU配准的边界，可以先缩小标定及传输范围，再批量回传给CPU完成实际几何采样；不能把CPU几何的数值工作融合进GPU，只在记录中留下CPU名称。

对继承默认或自动选择的实例，首版沿用当前设备选择，先优化执行效率。后续若加入基于数据规模与传输成本的设备规划，须单独实测并记录实际选择。界面可以建议尝试连续GPU或CPU，但不自动覆盖明确指定的设备。

## 内存和调度策略

复用现有 `StageStore`，增加按块填充与消费的能力；无需再建立与其竞争预算的第二套缓存。当前主路、额外历史缓存、状态和暂存分账，底层同一分配只计一次。

小信号可完整驻留时保留完整信号；大图使用有界块或已有磁盘载体。前序块一旦没有其他使用者就释放，不逐层长期保存完整输入输出。双缓冲或读取与计算重叠只有在计入峰值且实测获益后启用，作为后续优化。

预览继续按需取帧；正式任务可顺序推进完整范围；试算只准备所需窗口和模块明确要求的上下文。三者共享数值实现与来源规则，执行策略可以因访问模式不同而不同。

规划阶段发现能力或预算不足时，按片段使用兼容执行器并记录原因。数值异常、输入非法和已开始产生副作用后的失败正常报错，不能静默重跑、重复导出或将算法错误伪装成优化回退。

## 分阶段交付

每个阶段独立开关、独立对照，再测组合收益。性能计数随对应改造同步交付。

| 阶段 | 主要交付 | 主要代码位置 | 完成条件 |
| --- | --- | --- | --- |
| 一 | 固定CPU几何索引与掩码复用，执行计划骨架，基准与调用计数 | `geometry.py`、`sequence_engine.py`、拟新增 `execution_plan.py`、`performance.py` | 静态索引按有效计划构造一次；合法参数与异常行为一致；单独报告收益 |
| 二 | 首批局部需求推导、按块向前执行与紧凑主路交接，先CPU再GPU | `module_registry.py`、`module_contracts.py`、`sequence_engine.py`、`stage_storage.py`、`gpu_pipeline.py` | 本例ROI仅处理必需像素；无额外消费者时不生成全图浮点中间量；完整数值和来源一致 |
| 三 | 连续GPU前序批量，小信号g²连续输出批次，批量回传及交付适配 | `gpu_pipeline.py`、`correlation.py`、`gpu_moments.py`、`sequence_processing.py` | 调用和回传随批次数增长；重建、取消、进度和导出正确 |
| 四 | 显式混合设备的范围与传输分组，边界与预算验收，任务详情记录计划 | `gpu_pipeline.py`、`resources.py`、`performance.py`、任务详情 | CPU实例仍实际在CPU执行；传输范围可核对；紧预算及异常回退通过 |

第一批完成后，再逐项扩展带邻域的需求推导、复杂旁路、统计绑定和插件能力。初版优先将本次ROI均值与点采样两类流程变成可组合模块能力，避免一次重写全部算法。

运行详情按需展示“哪些模块合并为一块执行、实际计算范围、所选设备、块大小、保存与释放方式、未优化原因”。主工作流无需新增用户必须设置的调度参数。

## 验收与性能目标

### 正确性与生命周期

- 保留兼容路径和独立实现作为对照，对全部输出检查轴、形状、dtype、有限性、数值、语义、坐标和来源；本例来源逐条及逐字节一致，CSV字段完整核对。
- ROI有效值使用本轮 `rtol=2e-13`、`atol=2e-13` 的既定比较标准，并报告实际误差；来源时间浮点沿既有严格容差，整数时间、帧号和坐标精确核对。
- 覆盖正零负τ、不同步长、跨256重建、NaN/Inf、近零均值、极小涨落、独立与共同有效空间均值、非零点、不同几何及非连续布局。未支持的优化组合须正确进入兼容路径。
- 用多种块大小核对结果，验证块边界不会合帧、改变W/τ含义或重置周期计数；W和Q输出率不标作输入帧率。
- 加入上游完整图像截流、多个旁路、统计绑定及插件的对照，确认需求不会误删，输入校验不会被局部计算绕过。
- 紧预算下检查真实底层分配、输入输出交接峰值、GPU异步消费者和ROI视图所有权；检查取消、算法失败、磁盘不足及来源变化后的未完成标记与释放。
- 浏览器验收打开、播放、精确定位、阶段检查、试算、正式运行、结果对比和导出重开，原始数据数值不受处理修改。

### 同机工程目标

以下是首批优化组合后的目标，尚未测得；仅用于同一机器、同一文件、相同模块参数、预算和完整导出的验收。保持与现有基准一致的已有OS文件缓存条件，进程启动时间另外列出。

| 流程 | 当前工作台 | 首批目标 | 独立实现参照 |
| --- | ---: | ---: | ---: |
| ROI均值 CPU | 46.80秒 | ≤7秒 | 4.61秒 |
| ROI均值连续 GPU | 9.28秒 | ≤4秒 | 2.71秒 |
| 单点 CPU | 49.54秒 | ≤4秒 | 2.58秒 |
| 单点连续 GPU | 8.68秒 | ≤3秒 | 2.02秒 |

混合设备尚无同策略的局部专用版计时，先验收实际传输范围与往返次数下降，再据同策略复测设定时间目标。不能以改为连续GPU后的成绩代替原混合策略的优化收益。

单点全零案例用于性能与中间信号核对，科学数值验收同时依赖有效ROI及非零点。上述目标不外推到全图、全源统计、插件、磁盘冷读或任意大数据流程。

### 记录与复测方法

沿用现有独立工具，在优化关闭与开启、CPU、原混合配置、连续GPU之间轮换串行新进程，每组至少3次。每个阶段先单测，再测组合，保留每次原值、中位数、源码哈希、输入修订和完整输出核对。额外报告首次读取与已缓存读取，不能将应用新进程等同于磁盘冷启动。

除完整任务时间外，记录计划构建、静态索引构建、读取、运算、主机等待、传输、来源和输出；互斥主机分段不能与嵌套诊断重复相加。CUDA事件区间与覆盖率单列，抽样设备时间不外推为全部内核耗时。

新增关键计数包括每模块实际消费的像素与样本、静态索引构建次数、前序重算次数、GPU调用次数、主机回传次数与字节、实际批次数、主路与暂存峰值、释放字节及回退原因。本例10284帧仍需完整解码；若以后优化源读取，须单独对照，不混进本轮执行规划收益。

本例结构验收要求ROI前序标定像素数从5133772800降到385526592，输入读取保持10284帧。若输出块长为256，9284个结果应约37批回传，可先设最终结果回传不超过40次、小信号g²启动降至几十次的目标；预处理内核、初始化及显式CPU边界单独计数。新增批量内核需纳入CUDA事件覆盖说明。

验收依据是完整工作流更快且结果可核对，显存或GPU占用率仅用于解释资源状态。小ROI和双路小信号不需要占满显存。

## 本轮交付边界

本轮方案不增加算法模式，不更改用户模块顺序，不删来源和默认图形导出，不暗降精度。保留现有NumPy / CuPy依赖即可开展首批改造；读取预取、双缓冲、更广泛的邻域融合和自动设备成本模型留给后续独立实测。
