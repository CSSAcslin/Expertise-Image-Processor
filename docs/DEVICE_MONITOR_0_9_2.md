# 0.9.2 设备监测与 GPU 计时

0.9.3继续沿用本页的计时口径，新增连续输出块内核的CUDA事件覆盖；实际执行范围与批次见 [通用执行说明](PROCESSOR_EXECUTION_0_9_3.md)。

这次更新把设备状态放到预览和处理共用的主工作台，方便观察播放、阶段检查、试算及正式运行时的资源变化。运行设置负责预算配置，主界面负责持续观察，任务详情负责保存运行计时。

## 布局与交互

设备监测位于主界面右下角，与模块参数共用右侧宽度。上部继续显示模块参数，下部是监测区，分界可拖动并保存；设备面板可独立折叠及暂停。中央数据 / 结果预览、运行栏和底部任务记录保持各自位置。

四个小图统一采用近 2 分钟的时间窗、约 2 秒的采样周期、固定 0–100% 纵轴，并附当前数值。CPU / 内存和 GPU / 显存并列，避免把显存容量占用误当作 GPU 运算占用。多卡按设备选择，缺失读数画成断点，不能用 0 代替未知。

曲线下方的「资源明细」可展开查看当前进程内存、可用系统内存、任务 / 检查预算、原值缓存容量 / 帧数及各工作进程内存。它随曲线的同一次采样刷新，暂停、折叠和页面隐藏时一同停止；进程明细复用缓存，不额外读取进程内存。运行设置已移除这块重复读数，只保留预算配置与运行环境。

页面隐藏、监测区折叠或用户暂停后停止前端轮询。恢复后保留时间断点；曲线历史和设备数量有上限。小屏默认折叠，通过顶栏「设备状态」图标或「窗口 → 设备状态」开启；展开时占用实际布局空间，不在画布、任务记录和运行栏上增加遮挡层。

## 数值口径

| 项目 | 曲线与数值 |
| --- | --- |
| CPU | 整机忙碌百分比；本程序各工作进程 CPU 合计。都按全部逻辑核归一到 0–100%，不能把单核 100% 当成整机满载。首个样本没有时间差，显示未知。 |
| 内存 | 系统总量减可用量，附已用 / 总量；本程序显示工作台、数据读取、阶段检查及计算进程的 RSS 合计，属于进程工作集口径，共享页可能重复计入。 |
| GPU | NVIDIA 驱动提供的整卡 `utilization.gpu`，表示采样窗口内设备运行内核的忙碌比例。不是本程序专属占用，也不等于 FLOPS 达成率。 |
| 显存 | 整卡已用 / 总量；本程序进程显存由驱动提供。WDDM 无法提供时显示未知及原因。保存的显存预算仅为上限，不是预分配或占用目标。 |

后端复用有界采样缓存。读取 CPU 不睡眠等待，读取 NVIDIA 数据有超时和数量限制，不创建 CUDA 上下文。没有 NVIDIA GPU 时，CPU 与内存仍可显示；GPU 不可用及读取错误明确呈现。

## 任务计时

主机分段仍是互斥的墙钟耗时，包含 I/O、传输及同步等待。`gpu_submit`、`upload`、`download` 不会改名冒充内核时间。

新字段 `performance.gpu_device_seconds` 是抽样且已完成的 g² 融合内核调用区间的 CUDA 事件累计值；`performance.gpu_timing` 保存范围、状态、已计时次数、未抽取次数、首调排除次数、容量排除次数和待完成次数。覆盖四类融合调用：逐样本累计、批量累计、结果与计数、仅结果。

每种调用签名的第一次实际计算照常执行，但排除计时，避免首次编译等待混入。每类内核前 8 次调用进入采集判断，之后每 32 次抽取一次；显示抽样累计，不对未测调用外推总时间。逐次事件记录在微小内核上会有明显测量开销，抽样用于限制这种扰动。

选中的调用在当前流记录起止事件；事件对数量有界，运行中只检查已完成事件，容量不足时跳过采集并记录次数，不为每次采集强制同步。收尾等待剩余事件完成，再保存指标。失败或取消保留已采集数据及状态。

该数值是设备时间线上的已覆盖调用区间，可能包含调度间隙，未覆盖其他 CuPy 运算；不代表全流程所有内核的纯执行总和。纯内核总量 `gpu_execution_seconds` 继续为空，避免伪造完整覆盖。CPU 运行、只出现首次调用的小任务及旧记录均明确显示自身状态；历史耗时不能补算。设备计时与主机分段可能重叠，不能相加计算总耗时。

计时口径依据 [CuPy 性能测量与暖机说明](https://docs.cupy.dev/en/stable/user_guide/performance.html)、[CuPy CUDA Event 接口](https://docs.cupy.dev/en/stable/reference/generated/cupy.cuda.Event.html) 和 [CUDA Event elapsed time 定义](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__EVENT.html)。事件区间与纯内核活动时长须分别解释。
