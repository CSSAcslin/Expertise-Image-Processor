# 固定 CINE 流程：独立 CPU / GPU 与工作台对照

本实验回答两个问题：去掉模块执行器本身能省多少时间，以及为这条固定流程编写专用执行代码还能省多少时间。两者分别测量，不能把执行规划改变得到的全部加速称为模块函数调用开销。

分别测量两条真实保存的流程：最新的配准后 `(0,0)` 单点流程，以及此前的132×142 ROI均值流程。两者的数据、几何和关联参数相同，采样含义不同，计时及验证分开保存。

## 数据与计算

使用此前对照的 `Atip10000fps.cine`，10284 帧、600×832、uint16，文件 10267926620 字节。来源修订为 `e7b1451d94380189e5824abc1aa25963f4d897b4501069cdef1ef82fe09c1b7c`。

固定六步骤：保留全时间范围 → 每像素 float64 除以 4095 → 最近邻固定双幅配准（dx=2、dy=4，无镜像）→ ROI（x=140、y=207、132×142）→ 左右分别作有限值空间均值 → W=1001、τ=0、步长1的 g²。

最新单点案例保留相同时间、标定、配准和g²参数，用 `point_extract(x=0,y=0,output=main)` 取代 ROI / 空间均值，实际为五步骤。输出契约为 `pixel_g2`、`spatial_operation=null`，独立代码直接提取两路点值，没有伪装成1×1区域均值。

最后得到 9284 个 float64 标量。它是区域均值信号的 g²，不是逐像素 g² 的空间平均。关联使用 float64 波动累计、共同有效配对，每 256 个输出重建基准和累计量；GPU 禁用 FMA，不改成前缀和或低精度累计。

## 独立代码

- [direct_cine_flow.py](../tools/direct_cine_flow.py)：直接写出的 NumPy / CuPy 计算，仅复用 CINE 解码器。没有调用 SequenceEngine、DevicePipeline、模块算法执行入口、生产 RollingMoments 或生产 GPU 内核。
- [direct_cine_exports.py](../tools/direct_cine_exports.py)：从本轮读取器的真实时间和帧号独立重建来源、索引与 CSV，复用公共绘图导出函数生成 PNG/SVG。没有复制旧数值或旧来源文件。
- [benchmark_direct_flow.py](../tools/benchmark_direct_flow.py)：串行调度新进程、交替组别、核对全部输出、记录文件哈希和汇总中位数。

`literal` 仍在完整图像上标定、配准，最后裁 ROI。它保留相同的科学顺序和 GPU 批64关联累计，用于判断移除模块执行器的收益；读取 / 传输 / 输出的调度仍与工作台有区别，不能把二者的差值直接当成纯函数调用成本。

`specialized` 针对本例固定、逐像素标定和最近邻配准，预先合成 ROI 对应的传感器采样坐标，只处理真正被消费的像素。每个像素仍先标定再取均值；GPU 批量预处理并保持双路信号驻留，使用一个独立的串行 float64 内核完成这条小信号的关联。累计顺序和每256输出重建规则保留。

本例可以这样前推：标定没有全图统计依赖，配准的采样坐标及有效掩码固定，ROI 以外的像素对最终均值没有贡献。这不是对任意插件、空间邻域算法或全源归一化都成立的通用变换。

全帧标定处理 5133772800 个像素；专用路径只处理左右 ROI 的 385526592 个像素，约为前者的 7.51%。原始 CINE 仍完整解码，未用预先解码文件替代输入。

## 测量口径

环境为 Ryzen 9 9950X、RTX 5070 Ti、Windows、项目 Python 3.12.10 / CuPy 14.2、CUDA 13。以此前 CPU 保存运行的参数和预算为基准；GPU 混合组保留 CPU 配准，连续 GPU 组显式把启用节点设为 GPU，单独列出。

ROI案例8组各3轮，最新单点案例5组各3轮，共39次正式处理。每轮新 Python 进程，组别顺序轮换，所有工作串行。先做原数据数值预检查，因此主要反映已有 OS 文件缓存的情况；没有清空系统文件缓存，也不声称是磁盘冷启动基准。两批实验分别冻结源码；扩展单点前，ROI版工具已保存到原报告目录的 `code-snapshot/tools/`，旧路径同时通过回归。

完整处理计时包括打开输入、设备初始化、读取、计算、来源 / CSV / 曲线导出及收尾。进程时间额外包括 Python 启动和导入。读取与计算分段保留主机等待，不能当成纯 GPU 内核时间。最后的数值、来源、CSV、契约校验在计时外。

GPU 专用实现的设备内存池上限为512 MiB，按32帧传输块运行；工作台保留原运行的预算。上限不是预分配。专用路径只保留当前原帧、ROI 块及约161 KiB双路信号，不把全序列 float64 大图装入内存。

另跑 CPU、连续 GPU 和混合 GPU 的独立诊断，结果只用于定位调用，不计入正式中位数；嵌套累计时间不相加当成总时间。当前 Python / NumPy / Matplotlib 环境的默认 cProfile 内建调用监测出现根调用与绘图累计失配，已用无真实数据的最小例复现；最终诊断改用 `builtins=False` 重新执行三组，根函数均正常记录一次。旧异常累计行保留在原始报告中作审计，未用来解释绘图或计算成本。

**该点本身没有有效 g²：** 独立驱动工作台的全部前序阶段、采集10284×2双路缓冲后，确认两路在所有帧均为0，均值达不到 `min_mean=1e-9`，原程序9284个输出全部为NaN。没有修改点位或跳过计算来制造加速。

不能只靠NaN输出相同判定正确。额外将工作台完整中间信号与6次独立CPU / GPU运行逐值比较，每次20568个值全部一致；非零有效点的合成CUDA测试同时要求g²输出全部有限并与CPU对照。该组用于结构和性能诊断，下面的ROI案例提供9284个有效g²数值的完整精度对照。

单点专用路径只标定每帧真正消费的两个像素；仍完整读取同一CINE。它依然执行同一float64关联累计与重建规则，不根据全零数据预先返回NaN。

### 差距的位置

1. **最大的提升空间是上游按整幅图计算，ROI 消费范围太晚才生效。** 两个完整图像 CPU 版本均约46秒。只移除模块执行器没有带来数量级收益；将固定 ROI 需求投射回传感器坐标后，每帧浮点处理量从499200像素降到37488像素，同时保留相同的逐像素标定和后续均值含义。
2. **CPU 配准还重复构造静态采样索引。** ROI案例的一次独立 CPU 诊断中，`Geometry.apply` 调用10284次，子树约19.76秒；`Photometry.apply` 调用10284次，子树约15.40秒。配准内部每帧重复 `astype` / `clip`；诊断中 `clip` 共20632次、约3.89秒。`stack` 10284次另约3.58秒。两条链共享这段完整标定 / 配准前缀；静态坐标、有效掩码及拷贝布局可以预编译并复用。上述诊断时间不当作无剖析正式耗时，也不把子树和其子函数重复相加。
3. **混合 GPU 在大图边界来回传输。** 正式三轮中位分段：CPU计算27.61秒、GPU主机调度11.08秒、回传含等待18.61秒、上传含等待1.95秒。一次诊断记录19568次主机回传，含每帧标定结果及最终标量输出。直写完整图像混合版改善了索引和具体调度，但保留往返仍需38.02秒。它与工作台的传输计划并非完全相同，不能将24.98秒差值全称为模块函数调用开销。
4. **连续 GPU 仍按微小操作逐次驱动。** 工作台实际有28370次融合 g² 调用、9284次最终标量回传；专用版对整段双路信号用一次独立关联调用，最后批量回传。前序 GPU 预处理也从逐帧全图运算变成32帧 ROI 批量归约。未对抽样 CUDA 事件外推总内核时间。
5. **来源映射目前占比较小，前序阶段也已每帧只算一次。** CPU / 连续 GPU / 混合 GPU 的来源分段中位数分别约0.245 / 0.261 / 0.269秒。每轮读10284帧，每个前序阶段执行10284次，双路主路存储仅164544字节。继续扩大缓存无法消除已经只计算一次的大图工作。

### 下一轮后端更新的优先级

| 优先级 | 改造 | 验收重点 |
| --- | --- | --- |
| 1 | 对可证明局部等价的标定 / 固定最近邻配准 / ROI 链编译所需像素域 | 模块逻辑顺序与来源记录保留；全源统计、邻域依赖及插件明确回退；完整数值和坐标验证 |
| 2 | CPU 几何采样索引及掩码一次构造；减少全图转换、`clip`、`stack` 与复制 | 多几何、正负偏移、无效像素和随机访问仍正确；工作区有界 |
| 3 | GPU 批量执行前序，连续一维关联批量产出及回传 | float64、联合有效规则、256输出重建和取消保留；不把全部中间图存到显存 |
| 4 | 对显式 CPU / GPU 边界编译较小的必需数据域 | 尊重实例设备选择，报告实际传输范围；不暗改 CPU 配准为 GPU |

因此应保留模块化配置，改造它生成的执行计划；本实验没有给生产程序硬编码这六个模块。

### 验证与记录

- 首批17项、扩展单点后23项定向测试通过，强制真实CUDA。涵盖跨256重建、NaN/Inf、独立空间均值、真实点提取和共同有效配对、CPU / GPU、完整来源导出及设备策略。
- ROI正式24轮共核对222816个有效输出值，全部形状、dtype、有限性掩码、契约和设备策略通过；最大绝对误差 **2.220446049250313e-16**。CPU专用版与原CPU结果逐值相等。单点15轮另核对139260个NaN输出位置，并额外核对6×20568个中间信号值，不能混称为有效g²精度测试。
- 每轮9284条来源记录均逐字节一致，完整CSV核对通过，PNG/SVG正常生成；导出器不额外读取图像像素。
- 测量前后所有计算源码及实验工具 SHA256 一致。CPU / GPU 原始输入、旧输出、工作台会话和资源设置均未修改。
