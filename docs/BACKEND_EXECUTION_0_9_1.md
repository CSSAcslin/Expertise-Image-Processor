# 0.9.1 后端执行与来源索引

0.9.1 优先清理来源映射的重复遍历和前序数值回算。模块顺序、参数、float64 关联累计、必要的周期重建和显式 CPU/GPU 选择保持不变；普通播放继续按需读取。

## 来源映射改为增量索引

固定 τ 的每个输出不再重新扫描全部 W 对时间。新增 `WindowTimeIndex`，在窗口移动、扩大和缩小时更新进入及离开的配对，维护时差之和、已知时间配对数和精确极值。正负延迟、未知时间、不规则时间、逆向和随机访问均从真实上游时间计算。

时间引用透传节点与裁剪、抽样索引变换合并查询，避免逐模块构造相同字典。来源修订、源帧号、真实时间、贡献范围及非时间轴语义仍保留。

每个关联实例只保留当前实际使用的延迟，索引数组总额度最多为 `min(8 MiB, 任务份额/64)`，在多个实例间分配。W=1001 的索引数组实际为 64 KiB。配对时间查询次数随所需样本数线性增长，树更新为每次 O(log W)；索引不随完整 T×Q 增长。超大窗口无法在索引额度内建立时，保留有界的直接查询路径，并记录回退次数。

元数据的平衡求和可能与旧版逐项求和有舍入差别；不规则时间的平均时差按明确容差核对，配对范围、已知数及极值保持严格一致。时间已知配对数与 g² 的像素有效强度样本数独立。

## 压缩后的主路结果独立保存

执行器从重复时间消费者的直接上游选择合适的压缩结果，使用按需填充的主路存储。当前覆盖能力已知、逐样本独立的内置前缀，例如标定、配准、ROI、点提取及逐样本空间统计。

代表性流程为：

```text
按块读取 → 标定 → 配准 → ROI → 均值
                           ↓
              独占的整段双路信号和时间引用
                           ↓
                 g² 滚动、重建和导出
```

缓存不再让大图挤掉双路标量。主路存储的每个样本至多填充一次，正式任务按最多 32 个样本的有界块准备；生成完成的区域脱离原始大图底层分配，已消费的前序缓存及时释放。周期性关联重建继续执行，但直接读取已保存的信号，不重新标定、配准和归约。

实际策略记录为 RAM、设备数组或临时磁盘。主路工作数据与额外历史 LRU 缓存分别计入预算；分配时合计整个流程可能同时存活的工作数组、保留状态、时间索引、主机传输暂存及实例上限。GPU 驻留也为原有工作区和保留状态留出空间，不占满显存。

整段结果放不下时可使用按样本读写的临时磁盘载体，内存只保留有界索引和当前块；磁盘不足时，此项可选优化保留原有有界读取路径。阶段检查或单次试算不会为了局部样本建立整个磁盘载体。取消、异常和关闭时释放设备引用及临时句柄，未完成数据不作为正式结果发布。

宿主 LRU 同时修复了同键替换的字节重复计数，以及小 ROI/点视图间接持有大父数组的问题。缓存中的只读数据仍受保护，没有通过恢复写入标志去修改共享输入。

## 当前已实施边界

- 不对所有模块开放无条件原地修改。当前完成的是安全前缀的独占主路保存、按需填充和前序缓存回收，通用逐算子的所有权写入协议继续按 [更新方案](EXECUTION_TIME_OPTIMIZATION_PLAN.md) 推进。
- 前缀存在数据旁路、第三方插件、全源统计或参数引用依赖时，保留已验证的兼容路径，确保任务末尾的旁路交付仍有正确输入。后续再扩展跨这些依赖的阶段生命周期，不以清空缓存丢失旁路。
- 显式 CPU 配准不会因全局 GPU 自动变成 GPU。连续设备配置需由用户明确选择，实际设备进入运行记录。
- 来源文件与原有正式运行不改写；内存中的临时主路存储不自动注册为新的正式输入。

## 代表性真实流程复测

日期为 2026-10-28。硬件：Ryzen 9 9950X、RTX 5070 Ti；Windows 11、Python 3.12.10、NumPy 2.4.6、CuPy 14.2、CUDA 13.4 工具链。输入 10284 帧、600×832、uint16，流程为时间范围、标定、固定配准、132×142 ROI、独立双路空间均值、W=1001/τ=0/步长 1 的 g²，输出 9284 个 float64 标量。

主机预算 10240 MiB、预览 1280 MiB、计算缓存 2048 MiB、显存 10240 MiB。原配置只改变全局 CPU/GPU，配准实例始终明确选择 CPU。新版本各运行三次，使用新进程和独立输出目录，保留原配置与来源修订，完整比较数值和每条来源记录。

| 原设备配置 | 旧版已保存单次总耗时 | 0.9.1 三次中位数 | 比值 | 来源映射旧 → 新 |
| --- | ---: | ---: | ---: | ---: |
| 全 CPU | 565.18 秒 | 46.76 秒 | 12.09× | 280.68 → 0.245 秒 |
| GPU 混合，配准为 CPU | 700.64 秒 | 61.74 秒 | 11.35× | 283.22 → 0.288 秒 |

表中总耗时使用同一来源在计算进程中的互斥计时，包含准备、读取、计算、统计、来源及正常数值/图形导出，排除排队和进程启动。对应新进程完整耗时中位数分别为 47.23 秒、62.26 秒。旧值是此前各一次记录，新值是三次中位数；系统负载与缓存冷热未严格控制，不能推断所有数据都具有相同加速比。

两种原配置的全部复测输出与各自旧结果逐位相同，所有 9284 条来源记录及偏移索引逐字节一致。每个前序模块对每个输入样本只求值一次，读取请求降为 10284 次；旧 CPU / GPU 记录分别为 55568 / 57644 次。来源时间配对查询为 10284 次，加上各输出中心等引用，源引用查询为 19568 次。双路数值存储仅 164544 字节。

另做了显式全 GPU 配置对照，即将配准实例也设为 GPU；同样重复三次，总耗时中位数 **11.11 秒**，进程总耗时 **11.65 秒**，与旧 GPU 混合结果的全部数值及来源记录也完全一致。这是额外的设备配置对照，不能将其与“保持原设备配置”的后端收益混为一谈，也不会修改工作台当前流程里的 CPU 覆盖。

详细的匿名汇总见 [0.9.1 后端基准记录](benchmarks/backend_execution_0_9_1.json)。原始完整报告、运行配置、实验来源路径和输出保留在本机被忽略的 `.test-output/backend-update/` 与 `outputs/comparisons/`。

## 验证与工作台升级

最终完整 CPU/API/真实 CUDA 回归 **469 项通过、0 失败、0 跳过**。新增检查覆盖引用索引的线性访问、未知与不规则时间、阶段存储的 RAM/设备/磁盘路径、旁路保护、取消与恢复、紧预算、独占 ROI、实例工作区与驻留结果合计、临时盘不足回退及大序列局部检查。

CPU 与 GPU 的独立 Edge 工作流均通过；GPU 路径额外核对两个阶段检查、试算与正式输出一致、实际融合实现、NPY 下载、耗时持久化和大小窗口。已有 Starlette/httpx 的弃用提示不影响这些检查。

本机工作台在空闲时完成会话备份及独立端口恢复验证，再切换到 0.9.1；来源、任务标识、已保存结果和资源设置保留。刷新现有页面即可加载当前版本。若选择上述全 GPU 对照配置，需要同时将全局设备设为 GPU，并将配准实例的 CPU 覆盖改为 GPU 或继承；升级本身不替用户改变这个选择。

## 复测方法

使用启动工作台的同一个解释器：

~~~powershell
.\.venv\Scripts\python.exe -m pytest -q --require-cuda
.\.venv\Scripts\python.exe tools/benchmark_execution_time.py --baseline <原CPU运行目录>\run.json --repeats 3 --output-dir .test-output
.\.venv\Scripts\python.exe tools/benchmark_execution_time.py --baseline <原GPU运行目录>\run.json --repeats 3 --output-dir .test-output
# 显式改变实例设备的独立对照
.\.venv\Scripts\python.exe tools/benchmark_execution_time.py --baseline <原GPU运行目录>\run.json --repeats 3 --all-gpu --output-dir .test-output
.\.venv\Scripts\python.exe tools/smoke_acceleration_0_9_0.py --backend gpu
.\.venv\Scripts\python.exe tools/smoke_acceleration_0_9_0.py --backend cpu --port 8912
~~~

重放工具默认保留完整模块顺序、参数、精度、全局预算及显式设备，仅创建新的运行 ID 和输出目录。输出必须位于原来源及原运行目录之外；完整数值、有限值状态和来源逐项验证，平均时差允许规定的浮点容差，结构、帧、范围、计数和极值严格核对。

## 运行诊断字段

`run.json` 中每来源的 `modules.execution` 保存各阶段实际求值次数，以及 `main_storage` 的阶段、模式、大小、块大小、已填充样本、命中数和累计释放的前序缓存字节。累计释放量不是瞬时峰值，也不是整卡显存占用。

`modules.reference_execution` 保存查询次数、真实配对时间访问数、跳过的透传层数、索引构建和更新次数、数组额度与实际占用、超预算回退窗口数。原有 `modules.device_execution` 继续保存传输批次与样本数、缓存及关联累计计数。

主机分类保持互斥。新数据准备、磁盘写读和来源索引工作全部包含在计时内；没有把预计算移出任务计时，也没有把 GPU 调度时间填成纯 CUDA 内核耗时。旧运行不补造这些新字段。
